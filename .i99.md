## What to build

**Slice S18 · AFK**

Deliver reader/Table Reply action and contextual r shortcut through the existing writing desk to an Owner-only human Card save and generated Reverse link. Keep destination and target evidence explicit.

User stories covered: US031, US032. Design sections: §10.1.

### Detailed design contracts

The clauses below retain the actual source decisions; the acceptance criteria delimit this slice's deliverable. Adjacent consumers are implemented by their own dependent slices.

- **D238 · design §10.1:** Put a small `Reply` action next to the open agent Card's existing actions. Add `r` only in reader/Table navigation context when no input, editor, or modal owns the key. The command bar also exposes `reply`.
- **D239 · design §10.1:** Reply captures the target address, title, and authored fingerprint, then opens the existing writing desk with:
- **D240 · design §10.1:** Workspace fixed to `human` for this operation, independent of the cabinet's current Workspace.
- **D241 · design §10.1:** An empty claim title and an editable body beginning with the chosen relation word and `[[target]]`.
- **D242 · design §10.1:** A compact selector for `印证`, `反驳`, `放宽`, and `对应`, using their existing Relation kinds.
- **D243 · design §10.1:** A destination in the last successfully used human Topic, with an explicit destination label.
- **D244 · design §10.1:** The relation selector changes only the draft's supplied relation prefix. It must not rewrite text the user has already composed without preserving their edits. A bare Link plus no reply text cannot be saved as a completed substantive reply; the user supplies the thought and its conditions.
- **D245 · design §10.1:** Use a Side successor of the selected Topic's last suitable Regular entry for replies; if the Topic has no Regular Card, create its first Direct successor. Compute this from the current tree and normal placement rules at save time. The reply destination is in the human tree, not physically beneath the agent Card. Its Link and the generated Reverse link give the connection across Workspaces.
- **D246 · design §10.1:** If no recent human Topic exists, the editor offers the default human Topic `回应`. Create it only as part of the user's save path. Creating a Topic root and first reply is one transaction through a narrowly scoped Owner operation if no existing batch route can do so. Cancel does not create an empty Topic.
- **D247 · design §10.1:** Before saving, re-read the target. If it disappeared or its content changed, retain the draft and show the new target context; require the user's renewed Save with that visible context. The parent/destination is also checked fresh. A browser-local human reply preference is updated only after success, and a deleted/moved preference falls back to a valid Topic rather than following a stale numeric address blindly.
- **D248 · design §10.1:** The POST route is GUI-only and uses Owner access. There is no new MCP tool that writes human Cards. The normal Reverse link regeneration makes the reply appear on the agent Card, and agents can read that reply through existing tools. No body text is appended to the agent Card by Reply.
- **D281 · design §12.1:** GUI Reply save — Owner-only human creation through normal operations — No corresponding human-write MCP route
- **D308 · design §12.3:** Reply save fails — Keep editor text and destination visible; do not claim a saved human Card
- **D344 · design §14.1:** Reply — Agent target creates human reply; current cabinet Workspace irrelevant; empty human archive; cancel leaves no Topic; stale target keeps draft; keyboard does not fire in inputs

## Acceptance criteria

- [ ] **S18-AC01** Reply on an agent Card captures address/title/authored fingerprint, fixes this operation to human Workspace, and opens an empty claim title plus editable kinded target Link.
- [ ] **S18-AC02** Offer 印证/反驳/放宽/对应 through existing Relation kinds. Changing the supplied prefix cannot destroy user-composed text; a bare Link without reply substance cannot complete Save.
- [ ] **S18-AC03** Use the last successfully used valid human Topic with visible destination; save as Side successor at a freshly computed suitable Regular entry or first Direct successor for an empty Topic.
- [ ] **S18-AC04** If no valid recent human Topic exists, offer default 回应 but create root plus first reply only on Save, atomically through a narrow Owner operation if necessary. Cancel creates no empty Topic.
- [ ] **S18-AC05** Revalidate target fingerprint/existence and current destination before Save. Changed/missing targets retain draft and display fresh context for renewed Save; never follow a stale numeric occupant silently.
- [ ] **S18-AC06** Update browser-local destination preference only after success, and recover explicitly from moved/deleted Topics. Save failures retain draft and destination.
- [ ] **S18-AC07** Expose a reader action and reply command; r acts only in navigation context, never inside editor/input/modal. The reply sits in its human tree and Links back; do not append authored text to the agent Card.
- [ ] **S18-AC08** Keep the POST route Owner-only with normal GUI token checks. Add no human-write MCP tool; existing raw Agent human-write and human-Link-rewrite refusals remain.
- [ ] **S18-AC09** Verify normal Reverse link regeneration, user-visible success/conflict and focus behavior; document the public action/access boundary and wiki.

- Finished models retain statements, derivations, structure, parts, membership and build order. No new feature silently authorizes old-Card correction, live register rebuild, Bridge apply or historical migration.
- Existing-Card changes require a concrete reviewed report and exact user-selected scope. New pilot authorization covers only its identified new work. Preserve archive identity, authored fingerprints, sources, Link targets and Zone/Workspace boundaries.
- P6 Link-count caps/symmetric suppression and P10 Literature shortening/footprint remain dropped. The Link-scope/lease defect in #92 is separately owned; this PRD depends on its safety rather than claiming a prompt fixes it.
- Source/scratch tests, frozen simulation, installed versions, actual provider pilot, human usability and live historical apply are different evidence scopes. Required unresolved work stays named; no automatic extra correction cycle.
