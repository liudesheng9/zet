# 任务说明：让主题树从卡片盒里的文献长出来（所有任务共用）

本次运行读的是{{TITLE}}。你读其中一部文献的一节（任务文件写出它属于哪一部、它的引用键），把其中值得留下的想法写成**主题树**里的观点卡。下文的 `Key` 指本节所属文献的引用键。全部卡片用中文。按已加载的 `zettelkasten` skill 撰写、放置和链接卡片。

## 为什么这样做

Luhmann 有两个卡片盒。**书目盒**只放来源和读书笔记：在 ZET 里就是文献树，数字化流程已经建好。**正文盒**放他自己改写过的想法：在 ZET 里就是主题树。读书时他只写书目笔记。之后他问：这条笔记和正文盒里已有的卡片有什么关系？只有值得留下的，他才用自己的话写成新卡，放在它接续的那张卡后面，并链接远处的卡。你现在做的是第二步。

- 一张卡一个想法，用自己的话写，离开本书也能读懂。
- 卡片的价值在于它和盒子里其他卡片的关系：接续、限定、反驳、例示、同一机制在别处。
- 宁少而精。只写值得留下的想法，不复述全书。

## 整个卡片盒是一个整体

卡片盒里的文献不止一部。Luhmann 的正文盒来自他读过的全部文献：一个想法常常在第二本书里得到印证、限定或反驳，才值得写成卡。所以读本节时，不要只盯着这一部文献：

- 任务文件列出**其他文献里用词接近的笔记**。看它们说的是不是同一个机制、相反的结论或一个特例。
- 一个想法同时来自几部文献时，写成一张主题卡：正文写出共同的主张和各自的条件，用 `例示 [[Key/…]]`、`印证 [[Other/…]]`、`对照 [[Other/…]]` 分别链接它们。这样的卡把几部文献连在一起，最有价值。来源行写出全部来源：`来源：[[Key]] [[Other]]`。
- `sources` 只写本节的文献卡。其他文献的笔记写成正文里带关系词的 Link。
- 主题按概念组织，不按书组织：几部文献讨论同一概念时，放进同一个主题。

## 规划主题（任务 gt-001）

本次运行先做一个规划任务：读每一部文献各节的锚点和已有主题目录，决定本次运行的想法放进哪些主题。几部文献讨论同一概念时，规划成同一个主题，它的 `sections` 列出这几部文献的节号。之后每一节的任务都会列出这些主题。Luhmann 的主题很少，新想法大多接在已有的思路上，所以：

- 一个主题是**一个概念、一个追问**（例如 `敲竹杠`、`匹配外部性`、`组织模式的均衡`），不是本书某一节的标题，也不是本书的书名。
- 已有代理主题讨论同一概念时，用它：`{"id":"T1","existing":"379/0","sections":[2,7]}`。人类主题只读，不能作为 `existing`。锁定的代理主题也不能作为 `existing`（见下文"已锁定的主题"）。
- 只有盒子里没有这个概念时才新建：`{"id":"T2","title":"组织模式的均衡","body":"本主题追问：……（2–3 句）","sections":[1,3,5]}`。新建主题的数量有上限（任务文件写出），宁少勿多。几节讨论同一概念时，放进同一个主题。
- `sections` 写出哪几节的想法属于这个主题（节号）。一节可以属于几个主题。

答案：`{"topics":[…]}`。写到任务文件给出的答案文件，运行它的 SELF-CHECK，直到 `faults: 0`。

## 跨树链接（任务 gl-NNN）

各节的想法写入以后，还有一轮链接任务：每个主题树一个任务，列出这个主题本次新写的卡（from），其他主题本次新写的卡，以及盒子里用词接近的其他主题卡（to 的候选）。Luhmann 发现，最有价值的 Link 连接相距很远的卡片：同一个机制出现在另一个主题里，一个结论限定或反驳另一条思路。

- 只为真实的关系写 Link：对比、例子、同一机制、放宽、反驳、依赖。没有真实关系就不写。答案可以是空列表，这常常是对的答案。
- 用词相近不等于有关系。跨领域的 `类比` 或 `对照` 只在两张卡共享一个能说出来的机制时才写，并在句子里写出这个机制（例如 `类比 [[x]]：两者都是先投入、后议价，先投入的一方分不到全部回报。`）。说不出共同机制，就不写。
- 每条 Link 是一两句话，写进 from 卡的末尾：关系词在 Link 前，并写出关系是什么，例如 `对照 [[392/1|b]]：敲竹杠压低投资，这里的搜寻摩擦压低进入。`。
- to 必须是另一个树的卡，不能是主题根 `n/0`。每张 from 卡最多两条新 Link。
- 一句里只放这一个 Link，不用分号，最多 120 字。

答案：`{"links":[{"from":"391/1|c","to":"392/1|b","sentence":"对照 [[392/1|b]]：……"}]}`。写到任务文件给出的答案文件，运行它的 SELF-CHECK，直到 `faults: 0`。

## 资料（只读）

- **本节**：任务文件里附上了本节每张文献卡的全文、已经链接它的主题卡、用词最接近本节的已有主题卡。
- **主题目录** `{{TOPICS}}`：每个主题的地址、名称和第一句（代理与人类工作区），以及卡片盒里的全部文献。
- **全盒快照** `{{SNAPSHOT}}`：每张卡的地址和标题。用 `Select-String -Path "{{SNAPSHOT}}" -Pattern '议价|外包' | Select-Object -First 20` 查找，不要整份读入。
- **读卡**：用助手的只读模式读卡片正文和邻居（它拒绝一切写入）：

```
{{CALLENV}}@'
[{"tool":"get_card","arguments":{"at":"12/3"}},{"tool":"search_cards","arguments":{"query":"敲竹杠","limit":10}}]
'@ | {{TOOL}} call - -Allow "{{ALLOW}}"
```

你不直接写卡片。你只写答案文件，脚本检查后再写入。

## 步骤（全程最多 6 条命令）

1. **读本节**：任务文件已附上全文。在一条命令里查主题目录和快照里本节的 3–5 个核心概念。
2. **对话（可选，一条命令）**：用助手读最相关的 2–6 张已有主题卡和它们的邻居，弄清新想法接在哪张卡后面。
3. **写答案**（一条命令）：用 Write 工具或单引号 here-string 把 JSON 写到任务文件给出的答案文件。
4. **自查**（一条命令）：运行任务文件里的 `SELF-CHECK` 命令。它每行报告一个问题（编号、规则、说明），最后一行是 `faults: N`。
5. **修正**：改正答案里的全部问题，再运行一次自查，直到 `faults: 0`（最多三次）。
6. **回复** `OK`，或 `FLAG: <剩下的问题>`。

## 留下哪些想法

每个想法标一个种类 `kind`：

- `核心`：本节的中心主张或机制，用一般的话说出来。
- `关联`：本节的内容和盒子里已有的卡（其他主题卡，或其他文献的笔记）有真实的关系：放宽、推广、反驳、同一机制在另一个领域。这类卡最有价值。
- `有用`：可以用到别处的方法、判断标准或条件。
- `有趣`：出人意料或耐人寻味的结论，一个反直觉的结果，或一个值得追问的问题。
- `直觉`：一个结果为什么成立的直观解释，不用公式也能懂。

一节通常留 3–10 个想法，最多 {{MAX}} 个。一节确实没有值得留下的想法时，`ideas` 写空数组，并在 `none` 里写一句原因。

不要写成主题卡的内容：模型的设定和推导步骤、对作者原文的评述、离不开本书编号的论断。这些已经在文献树里。

## 怎样写一张主题卡

- **标题**：一句完整断言，最多 40 字，用你自己的话。不要照抄文献卡的标题（脚本会比较）。
- **正文**：80–250 字。写出主张、理由和**成立的条件**。不靠本书的编号（`式 (12)`、`命题 3`、`第 2 节`、`模型 1`）：写出编号所指的内容本身。
- **关系词**：每个 Link 都写在说明关系的句子里，句中 Link 前要有关系词。zt 认得这些词：`依赖`、`依据`、`承接`（论证的前提或上一步）；`例示`、`印证`、`案例`（例子或证据）；`对照`、`区别`、`相反`（对比）；`放宽`、`推广`、`扩展`（放宽或推广）；`对应`、`类比`、`相当于`（对应）；`反驳`、`质疑`、`反例`（反对）；`特例`（特殊情形）。`引出`、`见`、`由……可得`、`接着` 不是关系词：Link 前只有它们时，这个 Link 只是普通引用，自查会报 G10。来源行 `来源：[[…]]` 不需要关系词。
- **引用本书**：在用到它的那句话里链接来源笔记，关系词写在 Link 前：`例示 [[Key/3|a]]：本书的模型里……`、`对应 [[…]]`、`对照 [[…]]`。**不要用 `依赖 [[Key/…]]` 或 `基于`**：主题卡要自足，把它需要的假设写进正文。
- **来源行**：正文最后一行写 `来源：[[Key]]`（没有时脚本自动补上）。
- **其他链接**：除了父卡和来源，至少再链接一张相关的卡，写在说明关系的句子里。链到另一个主题树或另一本书的卡最有价值。
- 卡片语言规则见下文。

## 放在哪里（`at` 和 `as`）

按顺序判断，先满足的一条就是答案：

1. **盒子里已有同一主张的卡**：不写新卡。写 `"same": "<那张卡>"`，`body` 只写一句话，说明本书怎样印证或例示它（`例示 [[Key/3|a]]：本书在……中得出同样的结论。`）。代理卡会加上这句话；人类卡只记录，不改动。
2. **接着一张已有的代理主题卡**（它的下一步、限定、反驳或例子）：`"at": "<那张卡>"`。是论证的下一步时 `"as": "direct"`。是旁支、例外、反驳或例子时 `"as": "side"`。**第一句写出关系并链接那张卡**，Link 前要有关系词，例如 `本卡承接 [[12/3]] 的判断：……`、`本卡放宽 [[12/3]] 的完全契约假设。`。只写 `本卡把 [[12/3]] 用到……` 或 `由 [[12/3]] 可得` 不算：Link 前没有关系词，它只是一个普通引用。
3. **接着本答案里更早的一个想法**：`"at": "I1"`，`as` 同上。这样一节的想法连成一条论证链（Folgezettel），不要全部平铺。
4. **放进一个主题，但没有特别贴切的卡可接**（多数情况是任务文件列出的本次运行的主题）：`"at": "<主题地址 n/0>"`。主题还没有卡时，这张卡成为入口卡 `n/1`。否则脚本把它放在入口卡 `n/1` 的旁支上（`n/1|a`、`n/1|b`……），开出本节在这个主题里的一条思路。本节的其余想法接在它后面，连成这条思路（`"at": "I1"`）。第一句写出它和这个主题的追问的关系。
5. **本次运行的主题和盒子里都没有这个概念**：在 `topics` 里声明新主题（`"id":"T1"`，主题名是概念名，`body` 写 2–3 句它追问的问题），第一个想法写 `"at": "T1"`，它成为主题的入口卡。同一主题的其余想法接在入口卡或彼此后面（`"at": "I1"`）。主题名与已有代理主题几乎相同时，脚本把卡放进那个主题。
- 人类工作区的卡只读，不能接续。接续人类卡时，放进代理主题树（需要时新建主题），第一句写出关系，例如 `本卡推广 [[人类卡]]：……`。
- 文献树的卡不能作为父卡：这个流程只写主题树。
- 正文里可以用 `[[@I1]]`、`[[@T1]]` 链接本答案里更早的想法或新主题，脚本换成真实地址。

## 已锁定的主题（只读）

主人可以锁定一整棵主题树。锁定的树只读，这个流程也不写它：

- 锁定的主题卡可以读，可以作为相关语境，可以在正文里链接（`对照 [[7/2]]：……`）。
- 不要放进锁定的树：`at`、`same` 和主题的 `existing` 都不能指向锁定的卡。自查报 G12，写入也会被拒绝，脚本不会替你换位置。
- 任务文件把锁定的卡单列在"用词最接近的已锁定主题卡"一节，写着"已锁定：只读，可链接"；主题目录里标着 `已锁定：只读`。
- 一个概念的主题被锁定时，为它在 `topics` 里新建主题，或放进别的未锁定主题。

## 答案格式

```json
{"section": "Key/3",
 "topics": [{"id": "T1", "title": "外包合同的定价", "body": "本主题追问：外包价格怎样形成。价格怎样影响专用投资。"}],
 "ideas": [
  {"id": "I1", "kind": "核心", "title": "议价能力决定外包合同的价格", "body": "……例示 [[Key/3|b]]：本书……", "sources": ["Key/3|b"], "at": "T1"},
  {"id": "I2", "kind": "直觉", "title": "先投资的一方在议价中处于弱势", "body": "……", "sources": ["Key/3|a"], "at": "I1", "as": "direct"},
  {"id": "I3", "kind": "关联", "title": "……", "body": "本卡把 [[12/1]] 推广到外包。……对应 [[Key/3|a]]：……", "sources": ["Key/3|a"], "at": "12/1", "as": "side"},
  {"id": "I4", "kind": "核心", "same": "12/7", "body": "例示 [[Key/3|c]]：本书在……中得出同样的结论。", "sources": ["Key/3|c"]}
 ]}
```

- `sources`：这个想法来自本节的哪些文献卡（至少一张）。
- `id`：想法 `I1`、`I2`……，新主题 `T1`、`T2`……，各用一次。

## 卡片语言

标题和正文遵守 ASD-STE100 改写成的中文规则（`asd-ste100-zh` 技能）。下面的上限以本项目为准，检查脚本按这些数字检查。公式、链接和书中原话不受限制。

1. 一句只说一件事。
2. 描述句最多 40 字（公式和链接不计）。
3. 不用分号 `；`，写成两句。
4. 主动语态，写出动作者。
5. 动作用动词：`分析`，不写 `进行分析`。
6. 一个术语一个意思，与文献树里的用词一致。
7. 一个名词短语最多两个"的"。
8. 保留原书的语气：原书说"可能"就写"可能"。
9. 不堆叠限定，不用褒扬词：不写 `值得注意的是`、`深刻`。
10. 三个以上的步骤或条件用编号列表。
11. 公式用 `$...$`，`$` 成对出现。不要把含 `$` 的文字放进 PowerShell 双引号字符串。
12. 不写没有名字的指代：`那里`、`该卡`。写出它指的概念或结论。
