# 概念复核说明

你为一本已经消化的书判断它提出的概念与词库中已有的入口是否指同一件事。这是补充说明：`dsh-digest-base.zh.md`（或这本书的基础说明）里的卡片语言与写作规则照常有效。本说明只加这一件事：**判断意思，不写卡片**。

你只读任务文件，只写一个 JSON 文件。你**不调用 zt**，不改任何卡片，不建主题，不合并条目。你的回答是证据，不是动作：即使你判 `same`，也没有任何卡片会被创建或合并。

## 判什么

任务文件列出若干**提议**（`p001`、`p002`…）。每个提议给出它的标题、问题、陈述、假设、公式、来源，以及：

- **术语行**：本书术语表的四列（`术语`、`不用`、`意思`、`首次定义`）。`不用` 是这本书内部的用词约束，不是全局的同义词表，也不是"两个主题意思相同"的证明。
- **候选主题**：最多十个已有主题，带它们的问题和代表卡片。
- **候选陈述**：最多十条已有的陈述，带它们的假设、公式和来源。

你要给出三类判断：

1. `topic-concept`：提议的概念与某个候选主题是不是同一个问题。看到两张卡的陈述之后再判。
2. `restatement`：提议的陈述与某条候选陈述是不是同一处陈述。
3. `topic-home` 不用你判：工具只按来源证据报告它。

## 判据

- 只有**陈述的意思**相同才算 `same`。标题相近、共用术语、共用公式都是候选信号，不是判断。
- `same` 必须写出它成立的**范围**（`scope`）：在什么条件下两处说的是同一件事。范围与"假设"不同时，不要判 `same`。
- 公式相同而**假设不同**是 `different`：两处陈述讲的是不同条件下的两件事。数值、正负号、否定、范围也算陈述的一部分。
- 一个词出现在两处，不等于两处是同一个概念。本书可以给同一个词两个不同的意思（例如 `学习（个体行为）` 与 `学习（产业生产率）`）。按术语行与陈述判断，不要按词形判断。
- **证据不足就判 `uncertain`**，并在 `needs` 里写出还必须读哪张卡（写地址）。`uncertain` 不会自动变成创建或合并；它只是把缺的证据记下来。
- 标着"没有读到"的候选卡片，不得判 `same` 或 `different`：判 `uncertain` 并写出要读的地址。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）：

```json
{"schema_version": 1,
 "evidence_id": "冻结的证据集（任务文件给出）",
 "judgments": [
  {"kind": "topic-concept", "proposal": "p001", "candidate": "161/0", "verdict": "same",
   "entry": "161/1", "scope": "策略互补、参与者同时选择策略时",
   "assumptions": ["参与者同时选择策略"],
   "reason": "两张卡讨论同一个均衡条件与同一组问题。",
   "evidence": ["161/0", "161/1"]},
  {"kind": "restatement", "proposal": "p001", "candidate": "Rev2026/2", "verdict": "different",
   "reason": "公式相同，但候选卡以参与者对称为前提，提议的陈述没有这个前提。",
   "evidence": ["Rev2026/2"]},
  {"kind": "topic-concept", "proposal": "p002", "candidate": "157/0", "verdict": "uncertain",
   "needs": ["157/1 的正文与来源"],
   "reason": "候选主题的问题只写了一个词，代表卡片没有读到定义。",
   "evidence": ["157/0"]}
 ]}
```

- `verdict` 只能是 `same`、`different`、`uncertain`。
- `same` 必须有 `scope`；`uncertain` 必须有 `needs`。
- `evidence` 只写任务文件里列出的地址：候选的地址、它的代表卡片地址、本书的术语表卡。别的地址不算读过的证据。
- 每个（提议，种类，候选）只写一条判断；不要对同一对写两个不同的结论。
- `reason` 一句话（最多 40 字），写清判据，不抄原文。
- 每条判断只写这些字段：`kind`、`proposal`、`candidate`、`verdict`、`reason`、`evidence`，可加 `scope`、`assumptions`、`needs`、`entry`。别的字段会被拒绝。

写完后运行任务文件里的 `SELF-CHECK` 命令，按它报的错改到没有错误。最后只回复一行 JSON：`{"judgments":判断数,"same":same 数,"different":不同数,"uncertain":不确定数}`。

## 卡片语言

`reason`、`scope`、`needs` 遵守 `asd-ste100-zh` 技能：一句只说一件事，不用分号，主动语态。
