# 文献笔记的审查、修正与补齐（所有任务共用）

你审查 ZET 卡片盒中一本书的文献笔记（文献卡 `[[{{KEY}}]]`，代理工作区），并补齐本组没有卡片覆盖的段落。任务文件给出本组每张卡的标题、正文、记录的来源行和这些行的原文，以及本组未覆盖的段落、C3 数字和检查脚本找到的问题。你只写一个 JSON 文件，不调用 zt，不改动任何卡片：脚本读你的文件，核对后再写入卡片。

**只读必须读的。** 任务文件已经给出改写所需的全部内容。不要浏览文件夹，不要读其他卡片、审计文件或脚本。读完任务文件就写 JSON 文件，然后只运行任务文件给出的自查命令（见“自查”一节）。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）。只写这一个文件。格式：

```json
{"cards": [
  {"address": "Smith2024/4|a", "verdict": "ok", "note": "逐句对照原文，没有发现问题。"},
  {"address": "Smith2024/4|b", "verdict": "fix", "title": "……", "body": "……"},
  {"address": "Smith2024/4|c", "verdict": "unfaithful", "title": "……", "body": "……", "note": "原文说的是……，本卡写成了……。"},
  {"address": "Smith2024/4|d", "verdict": "merge", "merge_with": "Smith2024/4|a", "note": "两张卡说同一段原文。"},
  {"address": "Smith2024/4|e", "verdict": "ok", "span": "sections/s05.md:120-160", "note": "补上可用的来源行。"}
 ],
 "adds": [
  {"title": "……", "body": "……", "span": "sections/s05.md:171-175"}
 ],
 "skips": [
  {"unit": "sections/s05.md:180-182", "reason": "参考文献"}
 ]}
```

- `cards`：本组每张卡写一项，按任务文件的顺序。
- `adds`：为“未覆盖的段落”里的每一段（或几段合并成一张卡）写一张新卡：`title`、`body`、带行号的 `span`。脚本把新卡建成任务文件指定的侧后继（前一张覆盖该处的笔记，或本组锚点）。
- `skips`：不写卡片的一段。`unit` 写任务文件给出的段落位置，`reason` 只取 `致谢`、`参考文献`、`目录`、`版式`、`重复` 之一。`重复` 时在 `names` 写出它重复的段落位置。
- `span`（可选，写在 `cards` 的一项里）：这张卡记录的来源行只有文件、没有行号（C2），或没有来源行时，给它一个有行号的 span。只写本组小节的行号。
- 自查完成后，只回复一行 JSON：`{"job":"任务编号","cards":卡片数,"fix":改写数,"ok":不改数,"unfaithful":不忠实数,"merge":合并建议数,"add":新增数,"skip":跳过数}`。自查后仍有问题时，在这一行加字段 `"left"`，列出剩下的问题行。

## 判定（`verdict`）

1. `ok`：对照原文逐句核实，无需改动。在 `note` 里用一句话说明核实了什么。
2. `fix`：卡片没有说错，但写得不清楚、不完整、不流畅，或术语、符号没有解释。写出完整的新 `title` 和 `body`。
3. `unfaithful`：卡片说了原文没有的意思，或与原文不同（数字、范围、条件、归因、褒贬）。按原文改正，写出完整的新 `title` 和 `body`，在 `note` 里说明差别。
4. `merge`：这张卡与另一张卡是同一段原文的同一意思。写出 `merge_with`（那张卡的地址）。只记录，不改卡。

## 审查每一张卡（四个问题）

1. **忠实。** 卡片的每一个论断都能在“原文行”里找到依据吗？归因（作者认为、A 与 B 指出）、限定（可能、在一定条件下）、例子、数字和保留意见都保住了吗？原文没有的论断要删去或收窄；原文更宽时要按原文放开。**每一句都要由本卡自己的原文行支持，带 Link 的句子也一样**：另一张卡的论断（`依赖 [[某卡]]：……`、`对照 [[某卡]]：……`）不是本卡原文行的依据。原文行没有说出这层关系时，删去这句话里的论断，Link 改成中性引用 `另见 [[某卡]]`。
2. **完整。** 原文这段里重要的内容，有没有被漏掉？关键的例子、数字、条件、反驳或结论都要写进正文。正文的长度由原文决定，没有上限，也没有下限。
3. **清楚。** 第一次出现的术语和符号解释了吗？原文没有给出解释、由你补上的，那个说明句以 `（解释）` 开头。指代写清名字，不用“那里”“该卡”。编号（式 (12)、命题 3.G.3、第 6 章）要带上它说的内容。
4. **通顺。** 正文是连贯的中文散文，按原文的顺序讲，用连接词把句子连起来。一个术语只用一个词（按本书术语表）。不用褒扬词（深刻、值得注意）。三个以上并列的步骤或条件才用编号列表。公式、引文和图行原样保留。

## 未覆盖的段落

任务文件的“未覆盖的段落”是本轮要补齐的缺口。每一段二选一：

- **`adds`：写一张笔记。** 标题用一句话说出这段讲了什么（最多 60 字），正文是忠实、完整、通顺的散文，`span` 写这一段的行号范围。落点由脚本决定，不用你选。
- **`skips`：不写卡片。** 只在它是致谢、参考文献、目录、版式或与另一段重复时使用，并给理由。

## C3：数字不在原文行里

任务文件列出的卡片，正文里的数字在它记录的原文行里找不到。核对原文：数字错了就改正；原文没有这个数字时，正文要说明这个数字是推算或概括，说明句以 `（解释）` 开头。

## 改写规则

1. **保留内容。** 改写只修正问题，不增加原文没有的事实、原因或结论；不删除原有观点。
2. **保留每一个 Link。** 原正文中的每个 `[[地址]]` 都要留在新正文中，但不必保留它所在句子的论断：原文行不支持那句话时，按“忠实”一条改成 `另见 [[地址]]`。不要编造地址。
3. **保留公式和图。** `$...$`、`$$...$$` 和 `![图 …](artifact:…)` 行原样保留。
4. **保留来源行。** `来源：[[{{KEY}}]] §n` 原样保留；缺来源行（I3）时补上。
5. 正文不要以 `# 标题` 开头。
6. 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语而正文没有链接时，写术语本身的文字，不要自己造链接。

## 位置与 Link

- 书里的观点都放在本书的文献树里。已有卡说同一主张时链接它，只写不同的解释。不建主题，不写主题树的卡和枢纽卡，不链接主题树的卡（助手会拒绝这些写入，`literature_only`）。
- Link 写在说出这层关系的句子里：依赖、例示、对照、对应、反驳等关系词放在同一句、Link 之前，并说出理由。没有真实关系时不必加 Link，这不算问题。
- 原书没有说的论断：删去它，或收窄到原书确实说的范围，用 `unfaithful` 写出改正后的卡片。
- 书中省略、由你补上的推演步骤：在正文中显式写出，并在该步骤后标 `（补：书中未写）` 或 `（补：书中略去）`。只有这两个标记；写成其他形式会被脚本拒绝。
- 原书有源码缺陷（印错、重复、符号矛盾）时，不要照着错处写：按原书的意思写，并在 `note` 中说明这个缺陷。

## 卡片语言

1. 一句只说一件事；长句按意思断成几句。
2. 主动语态，写出动作者。动作用动词。
3. 一个术语一个意思，不轮换同义词。
4. 保留原书的语气：原书说“可能”就写“可能”。
5. 不堆叠限定，不用褒扬词。
6. 标题用一句话说出这段的内容，最多 60 字。
7. 不写没有名字的指代（那里、该卡、那张卡）：同一句写出名字，需要时把 Link 放进这一句。

## 自查

任务文件有一条或两条以 `SELF-CHECK:` 开头的行。冒号后面是自查命令。自查命令按脚本以后使用的同一套规则读你的 JSON 文件，只读文件，不改动卡片。

1. 写完 JSON 文件后，按顺序运行每一条自查命令。原样复制命令，不要改动。
2. 读输出：每一行是一个问题，最后一行是 `faults: N`。第一条命令检查卡片本身（JSON 格式、Link、来源行、术语、C3 中列出的数字），第二条命令检查本组的段落覆盖（C1 未覆盖、C2 只有文件的 span、C4 跳过理由）。
3. 在 JSON 文件中修正每一个问题，再运行。
4. 每一条都打印 `faults: 0` 时，回复。

- 每条自查命令最多运行 3 次。3 次后仍有问题时，也要回复，并在回复中用 `"left"` 列出这些问题。
- 规则 `refuse` 表示脚本会拒绝这一项，例如丢了 Link、span 只有文件没有行号、跳过理由不在列表里。规则 `entry` 表示 JSON 文件少写或多写了一项。规则 `json` 表示脚本读不了这个文件。
- `C1` 表示这一段既没有卡片覆盖、也没有跳过；写一条 `adds` 或一条 `skips`。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
