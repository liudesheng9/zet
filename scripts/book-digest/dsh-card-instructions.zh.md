# 卡片修正任务说明（所有任务共用）

你修正 ZET 卡片盒中一本书的卡片（文献卡 `[[{{KEY}}]]`，代理工作区）。检查脚本已经找出每张卡的问题。你只写一个 JSON 文件，不调用 zt，不改动任何卡片：脚本读你的文件，核对后再写入卡片。

本说明之后附上你的任务文件。任务文件给出每张卡的地址、类别、父卡、问题清单、标题和正文，有时还给出原文位置。

**只读必须读的。** 任务文件已经给出改写所需的全部内容。不要浏览文件夹，不要读其他卡片、审计文件或脚本。只有一张卡给出"原文"时，才读那几行原文。读完任务文件就写 JSON 文件。写完后只运行自查命令（见"自查"一节），不要用其他方法读回检查。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）。只写这一个文件。格式：

```json
{"cards": [
  {"address": "40/1|a", "verdict": "fix", "title": "……", "body": "……"},
  {"address": "40/1|b", "verdict": "split", "title": "……", "body": "……",
   "split": [{"title": "……", "body": "……"}]},
  {"address": "40/2", "verdict": "ok", "note": "问题是误报：……"},
  {"address": "40/3", "verdict": "merge", "merge_with": "40/1", "note": "两张卡说同一个观点。"},
  {"address": "40/4", "verdict": "unfaithful", "title": "……", "body": "……", "note": "原书没有说……"}
]}
```

- 每张卡写一项，按任务文件的顺序。
- `verdict`（判定）取下面一个值：
  1. `fix`：你改写了标题或正文。写出完整的新 `title` 和 `body`。
  2. `split`：只在问题清单有 `I2 … split candidate` 时使用，或这张卡确实有两个观点。句子太长（R2）只需断句，不要拆卡。`title` 和 `body` 是留下的第一个观点，`split` 列出新卡（通常一张）。脚本把新卡建为这张卡的侧后继。
  3. `ok`：不需要改。在 `note` 中用一句话说明理由，例如问题是误报。
  4. `merge`：这张卡与另一张卡说同一个观点。写出 `merge_with`（那张卡的地址）。不写 `title` 和 `body`。整理阶段决定是否合并。
  5. `unfaithful`：原书没有说这个观点，或说的不同。写出按原书改正后的 `title` 和 `body`，在 `note` 中说明差别。只在任务给出原文时使用。
- 自查完成后，只回复一行 JSON：`{"job":"任务编号","cards":卡片数,"fix":改写数,"split":拆分数,"ok":不改数,"merge":合并建议数,"unfaithful":不忠实数}`。自查后仍有问题时，在这一行加字段 `"left"`，列出剩下的问题行，例如 `"left":["40/1|a R2 (45 characters > 40) ……"]`。

## 自查

任务文件有一行以 `SELF-CHECK:` 开头。冒号后面是这个任务的自查命令。自查命令按脚本以后使用的同一套规则检查你的 JSON 文件。自查命令只读文件，不改动卡片。

1. 写完 JSON 文件后，运行自查命令。原样复制命令，不要改动命令。
2. 读输出。每一行是一个问题，格式是 `地址 规则 说明`。最后一行是 `faults: N`。
3. 在 JSON 文件中修正每一个问题。按"各类问题怎样改"一节修正。
4. 再运行自查命令。
5. 最后一行是 `faults: 0` 时，回复。

- 自查命令最多运行 3 次。3 次后仍有问题时，也要回复，并在回复中用 `"left"` 列出这些问题。
- 规则 `refuse` 表示脚本会拒绝这一项，例如丢了 Link。规则 `entry` 表示 JSON 文件少写或多写了一项。规则 `json` 表示脚本读不了这个文件。
- 拆分出的新卡在问题行中写作 `地址+split1`、`地址+split2`，按 `split` 列表的顺序编号。
- 拆分出的新卡除了链接原卡，还要有一个带关系词的 Link 指向另一张卡（I4）。原卡中属于新观点的 Link 可以移到新卡。

## 改写规则

1. **保留内容。** 改写只修正问题，不增加原卡没有的事实、原因或结论。不删除原卡的观点。
2. **保留每一个 Link。** 原正文中的每个 `[[地址]]` 都要留在新正文中（拆分时可以放进新卡）。不要编造地址。
3. **保留公式和图。** `$...$`、`$$...$$` 和 `![图 …](artifact:…)` 行原样保留，不改动其中的字符。
4. **保留来源行。** `来源：[[{{KEY}}]] §n` 原样保留。缺少来源行时（问题 I3），按任务文件给出的小节补上一行。
5. 正文不要以 `# 标题` 开头。
6. 拆分出的新卡也要有来源行，并用一句话链接原卡，关系词放在 Link 前，例如 `依赖 [[40/1|b]]：……`。

## 各类问题怎样改

- **R2（句子太长）**：在每个新陈述处断句。一句只说一件事。描述句最多 40 字（公式和 Link 不计）。
- **R3（分号）**：把分号两边写成两句。
- **R4（被动）**：写出动作者，用主动语态。原书没有写出动作者时才保留"被"。
- **R5（名词化）**：动作用动词：`分析`，不写 `进行分析`。
- **R6（术语）**：换成术语表中的术语。
- **R7（"的"太多）**：一个名词短语最多两个"的"。
- **R9（堆叠限定、褒扬词）**：删去 `值得注意的是`、`深刻` 这类词，保留陈述本身。
- **R12（标题）**：标题只陈述一个论断，最多 40 字，不用分号。
- **I1（标题不是论断）**：把标题改成一句完整的论断。
- **I2（太长）**：超过上限时拆成两张卡（`split`）。太短时判 `ok` 并在 `note` 中说明，或判 `merge`。
- **I3（没有来源行）**：补上 `来源：[[{{KEY}}]] §n`。
- **I4 与 L1（Link 没有关系类型）**：ZET 从 Link **紧前**的词读出关系。把下面一个关系词放在同一句中、Link 之前：`依赖`/`基于`/`承接`（以它为前提）、`例示`/`案例`（举例）、`对照`/`区别`（比较）、`放宽`/`推广`（推广）、`对应`/`类比`（对应）、`反驳`/`批评`（反对）。关系词必须说出两张卡之间真实的关系。只是提到某张卡、没有真实关系时，保留原句，在 `note` 中说明。指向父卡或主题根卡的 Link 可以保留为普通引用。
- **R20（编号代替内容，建议）**：`式 (12)`、`命题 3.G.3`、`第 6 章`、`模型 1`、`本节`、`§11.D` 这类编号要带上它说的内容：把编号换成公式、命题、模型或步骤本身的名字，或在同一句写出它说的内容。文献卡正文可以保留编号作次标签。只改这一句，不要重写其他句子。
- **R21（指代没有名字，建议）**：`那里`、`那儿`、`该卡`、`那张卡`、`这张卡` 在同一句没有 `[[…]]` 时，写出它指的是哪张卡、哪个模型或哪个概念，需要时把 Link 放进这一句。前一句里的名字不算。
- **I7（前提落在自己的来源上）**：主题树的观点卡用 `依赖 [[{{KEY}}/n]]` 靠在本书的文献树上。把前提写成自足的陈述：写出必要条件或假设本身；或者把这条 Link 改成真实的关系（`例示`、`对应`、`对照`）；或者说明这张卡属于文献树。只把 `依赖` 换成 `对应` 不算改好。
- **L2（Link 没有理由）**：在 Link 所在的句子中写出理由：两张卡之间是什么关系，为什么。
- **L3（同一目标链接多次，建议）**：同一张卡只在最相关的一段链接它，其余段落改为文字指代。
- **I6（标题和别的卡几乎相同，建议）**：先判断两张卡是不是同一主张。同一主张：判 `merge`，或把内容并到已有一张卡上。不同主张：改写这张卡的标题，把区别写出来。只凭标题相似不得删除或合并任何卡。
- **N1（整理阶段的要求）**：整理阶段读过全书结构后给这张卡的要求，例如"链接模型 [[…]] 的设定分卡，说明本卡放宽了哪条假设"。按要求改写，关系词放在 Link 前。要求与原书不符时判 `ok`，在 `note` 中说明。
- **E1（事件卡标题没有日期）**：在标题中写出年份（原书给出时间时）。
- **E2（事件卡缺少标签）**：正文改为下面的格式。原书没有给出的项写 `原书未写明`，不要编造：

  ```
  时间：……
  地点：……
  参与者：……
  经过：……
  来源：[[{{KEY}}]] §n

  证据作用：本事件例示 [[观点卡]] 的……
  ```

- **F1（发现卡缺少标签）**：正文按这六个标签写，顺序不变：`测量：`、`数据：`、`方法：`、`结果：`、`局限：`、`来源：`。原书没有给出的项写 `原书未写明`，不要编造。标签之后写一段 Link，说明这一结果支持哪张观点卡。
- **F2（来源行没有链接本书）**：`来源：` 行链接 `[[{{KEY}}]]` 或本部分的锚点，并写出小节。
- **F3（一张卡有多个结果）**：`结果：` 只写一个结果，带大小或方向。其余结果拆成新卡（`split`），每张一个结果。

## 抽查与模型卡（没有问题时）

任务文件的某张卡没有列出问题时，它是抽查：对照任务文件给出的原文核实这张卡，然后判 `ok`、`fix`、`split`、`merge` 或 `unfaithful`。

- 任务文件的类别是 `model` 时，这张卡是一个模型草稿，这一轮没有模型链负责它的来源核对：由你核对。对照原文核实标题和正文的每一个论断。
- 原书没有说的论断：删去它，或把它收窄到原书确实说的范围，用 `unfaithful` 写出改正后的 `title` 和 `body`。
- 书中省略、由你补上的推演步骤：在正文中显式写出，并在该步骤后标 `（补：书中未写）` 或 `（补：书中略去）`。只有这两个标记；写成其他形式（例如 `（补充：……）`）会被脚本拒绝。
- 原书有源码缺陷（印错、重复、符号矛盾）时，不要改写原书，也不要照着错处写：按原书的意思写，并在 `note` 中说明这个缺陷。

## 卡片语言

标题和正文遵守 ASD-STE100（简化技术英语）改写成的中文规则。经理已通过 `skills` 把 `asd-ste100-zh` 技能交给你：先按该技能写。本项目的上限与技能中的数字不同时，以本说明为准（检查脚本按这些数字检查）。公式、Link、图表代码和书中原话不受限制。

1. 一句只说一件事。描述句最多 40 字。
2. 不用分号 `；`。
3. 主动语态，写出动作者。动作用动词。
4. 一个术语一个意思，不轮换同义词。
5. 一个名词短语最多两个"的"。
6. 保留原书的语气：原书说"可能"就写"可能"。
7. 不堆叠限定，不用褒扬词。
8. 标题只陈述一个论断，最多 40 字。
9. 编号要带上它说的内容（`式 (12)`、`命题 3.G.3`、`第 6 章`、`模型 1`、`本节`、`§11.D`）：写出公式、命题、模型或步骤本身，编号可作次标签。`第一福利定理` 这类有名字的结论不算编号。
10. 不写没有名字的指代（`那里`、`该卡`、`那张卡`）：同一句写出名字，需要时把 Link 放进这一句。前一句里的名字不算。
11. 主题树的观点卡自足：正文写出它依赖的必要条件或假设本身，用 `例示`/`对应`/`对照` 表达真实关系，或把它放进文献树。只把 `依赖` 换成 `对应` 不算改好。
12. 标题和工作区已有标题区分开：同一主张写在同一张卡上，不同主张在标题里写出区别。相似标题提示（I6）只作参考，不得据此删除或合并两张卡。
