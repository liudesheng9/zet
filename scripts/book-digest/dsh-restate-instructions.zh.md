# 重述复核：同一陈述是否已经写在别处

你在书稿摘要的卡片循环里做一件事：判断一张**新卡**是否已经把另一张卡已有的陈述又写了一遍，并给出可执行的解决方式。只改新卡，绝不改已有的卡。

## 你看到的证据

每一对给你两张卡的**完整陈述**、各自的假设、公式与来源，以及三个**候选信号**：

- `relatedness`：当前相关度（TF-IDF 余弦），只说明用词相近。
- `title_similarity`：标题相似度。
- `共享公式`：两张卡的公式字符串完全相同。

三个信号都只是"值得读这一对"的理由，**没有一个是判断**。公式相同可以是同一陈述，也可以是定理与解读、或不同条件下的两个命题。你必须读完两张卡的陈述、假设和范围再判断。

## 三种判断

- `same`：两张卡说的是同一陈述，假设与范围相同。必须写出：
  - `canonical`：持有该陈述的那张卡（通常是候选卡）。
  - `scope`：为什么两边的假设与范围相同。
  - `remedy`：怎么解决。
- `different`：两张卡不是同一陈述。必须用 `reason` 说出区别：定义对经验发现、定理对解读、条件不同、符号相反、数量级不同、范围不同，等等。只靠公式相同不能判 `same`。
- `uncertain`：还缺证据。必须用 `needs` 写出缺哪份原文、哪个定义或哪个前提。两张卡都保留。

## `same` 的三种解决方式

只允许这三种；`remedy` 写错会被拒绝。

1. `distinct-implication`：把**新卡**改写成该陈述的一个推论或后果。写 `title` 和完整 `body`：
   - 正文是一张小而完整的陈述卡：二到三句，每句不超过 40 字，正文 40 到 300 字。用一句带理由的话链接终述卡，并在 Link 前用关系词（如 `依赖`、`例示`、`对照`、`对应`、`放宽`），例如 `本卡依赖 [[K/4|a]] 的定义：价格不变时两项效应都为零。这条推论只用于局部比较。`。
   - 正文不要出现 `## 同述入口` 一节。
   - 保留新卡原来的来源行（`来源：[[…]]`）。
2. `entry`：把**新卡**改写成一张普通的 Idea 入口卡。写 `title` 和完整 `body`：
   - 标题说清这是入口，例如 `斯卢茨基分解的陈述入口`。
   - 正文有 `## 同述入口` 一节，其中**恰好一个** Link，直接指向**终述卡**（不是另一张入口卡），并写出理由。
   - 保留新卡原来的来源行。
3. `existing-card-change`：解决需要改动**已有的卡**（合并、改写模型卡或模型分卡）。这时**不要写** `title` 或 `body`，也不要给 `remedy` 之外的东西；它会记为"待改已有卡"，由人另行授权。

规则要点：

- 已有事实陈述留在原处；已完成模型的陈述、推导、结构、分卡、归属与构建顺序都不动。本步骤只改写新卡。
- 一张新卡最多被一对解决：同一张新卡的第二处 `same` 会被拒绝。两张卡都被判 `same` 时，选真正持有完整陈述的一张作 `canonical`。
- 入口卡的 `同述入口` 只能指向同一工作区里存在的**实质卡**，不能指向自己、树根、锚点卡、枢纽卡或另一张入口卡。链条会被拒绝：直接写终述卡。若候选是锚点卡（`kind` 为 `anchor`，它是导航），不能写 `entry`：改写新卡为 `distinct-implication`，用关系词链接那张锚点卡。
- 改写必须保留原有来源行的每一个来源；不要新增没有来源的引用。
- 不要用近义词替换种类词来"解决"重述；不要把 `same` 写成 `different` 来绕过改写。

## 输出

写出一个 JSON 文件，检查通过后只回复一行 JSON：

```json
{
  "schema_version": 1,
  "evidence_id": "<证据文件里的 evidence_id>",
  "judgments": [
    {
      "card": "<新卡地址>",
      "candidate": "<候选卡地址>",
      "verdict": "same|different|uncertain",
      "canonical": "<same 时：终述卡地址>",
      "scope": "<same 时：假设与范围为何相同>",
      "reason": "<判断理由>",
      "evidence": ["<你读过的这一对的地址>"],
      "remedy": "<same 时：distinct-implication|entry|existing-card-change>",
      "title": "<改写后的标题>",
      "body": "<改写后的完整正文>",
      "needs": ["<uncertain 时：缺什么>"]
    }
  ]
}
```

- 每一对只写一次；重复且不一致会被拒绝。
- `evidence` 只能写这一对读过的地址（新卡、候选卡、终述卡）。
- 没把握的一对写 `uncertain` 并列出 `needs`；不要猜。
- 一个 `judgments` 里可以只写你判断过的对；未写的对会记为 `unjudged`，报告不完整。

## 自检

写完后运行任务文件里的 `SELF-CHECK`。它按同一套规则校验你的答案：schema、证据编号、配对、verdict、canonical、scope、remedy、正文里的 `同述入口` 与终述卡、来源是否保留、一张新卡是否只解决一次。改到没有错误为止。
