# 边界任务说明：假设的作用、反例与对照例

你为几个数学单元写出它们的边界。读者要知道每个假设为什么必要，也要知道一个定义的边界在哪里。本说明之后附上任务文件。任务文件给出每个单元的模型卡正文、证明的主线和证明分卡，以及原文。只读任务文件，不读别的文件。

## 要写什么

任务文件为每个单元写明“要写”什么：

- `hypotheses:H1,H2`（定理、命题、引理、推论）：为每个列出的假设写一项。
  - `role`：这个假设在哪一步用到，去掉它为什么证明不成立。两到四句。
  - `used_in`：用到它的证明分卡的地址（取自任务文件中的主线）。没有用到时写空字符串，并在 `role` 里写明原书为什么保留它。
  - `counterexample`：一个对象，满足其余全部假设，但不满足这一个，结论也不成立。写 `title`（一句话，最多 40 字）、`body`（对象和验证，三到八句，公式不计）、`supplied`（原书给出时为 `false`，你自己补写时为 `true`）。找不到严格成立的反例时，写 `null`。
- `example`（定义）：一个满足全部条款的对象，写出验证的计算。
- `non_example`（定义）：一个只违反一个条款的对象。在 `body` 里写明违反的是哪个条款，例如“(C2) 不成立”。另写 `clause`（条款标签）。

## 规则

- **先用原书。** 原书给出的例子、反例，照原书写，`supplied` 为 `false`。
- 补写许可写在任务文件开头：`none` 时只写原书给出的内容。`examples` 时可以补写例子、非例和反例，`supplied` 为 `true`，正文末尾标 `（补：书中未给）`。
- **补写的对象必须严格成立。** 逐条核对它满足哪些条件、违反哪个条件、结论为什么不成立。拿不准时写 `null`，不要编造。
- 卡片语言：一句只说一件事，不用分号，主动语态，每句最多 40 字（公式不计）。标题只陈述一个论断。

## 结果文件

用写文件工具把 JSON 写到任务文件给出的路径（只写这一个文件）：

```json
{"items": [
  {"unit": "Key/4|d", "hypothesis": "H1", "title": "假设作用：去掉连续性，函数可以跳过 c",
   "role": "步骤 3 用连续性找到 x0 右侧的点。函数不连续时，这一步不成立。",
   "used_in": "Key/4|d|a|3",
   "counterexample": {"title": "反例：符号函数跳过 0", "body": "取 f 为符号函数，区间 [-1,1]，c=1/2。……", "supplied": true}},
  {"unit": "Key/4|b",
   "example": {"title": "例子：x^2 处处连续", "body": "……", "supplied": false},
   "non_example": {"title": "非例：符号函数在 0 处跳跃", "clause": "C2", "body": "取 ε=1/2。……(C2) 不成立。", "supplied": false}}
]}
```

写完后只回复一行 JSON：`{"items":N,"supplied":M}`。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
