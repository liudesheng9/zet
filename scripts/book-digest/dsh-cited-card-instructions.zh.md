# 文献引用卡任务说明

你为一本书（文献卡 `[[{{KEY}}]]`）的参考文献写文献引用卡的内容。每篇文献一张卡。你只写一个 JSON 文件，不调用 zt，不写卡片的 Markdown 排版。

本说明之后附上任务文件：本次的文献（参考文献表的行号、原文条目、第一作者的姓、年份、题名）、全书原文的路径、脚本找到的候选行、本书的术语表和关系词。

## 先读全书，再写

书中的读书笔记经常漏掉引用，所以不要只看笔记，也不要只看候选行。对每篇文献：

1. 在全书原文里搜索它：第一作者的姓（拉丁字母，也看中文里的同一个姓）、年份、题名中的词。正文、脚注、附录都要看。原文是中英对照的，同一处引用常有英文和中文两行。
2. 读每一处引用前后的段落，弄清本书在那里用这篇文献做什么。
3. 只根据你读到的原文写。不要用你在别处知道的关于这篇文献的知识。原文没说的，不写。

## 每篇文献写什么

- `row`：任务文件给的行号，原样照抄。
- `short_title`：这篇文献的中文短题名，不超过 20 个字，照它的题名意译。
- `why`：`为什么引用`，1–3 句。本书在哪里、为了什么引用它。
- `role`：`在本书研究中的作用`，1–4 句。它为本书提供了什么（问题、方法、数据、结果、对照），本书的哪一部分用到它。
- `relationship`：`本书与该文献的关系`，1–4 句。本书继承、推广、对照或反驳了它的什么。`relations` 里的每个关系词都要在这里出现。
- `relations`：关系词，从下面七个中选一个或几个：
  - `依赖`：本书用了它的结果、方法或数据。
  - `推广`：本书推广或放宽了它。
  - `对照`：本书拿它作对照。
  - `反驳`：本书反驳它。
  - `印证`：本书的结果与它一致。
  - `参照`：本书参照它的做法或框架。
  - `背景`：只作背景。
- `locations`：本书使用这篇文献的每一处，最多 12 处。每处写 `line`（全书原文的行号，第 1 行起数）和 `use`（一句话：本书在这一处怎样用它）。同一处引用的英文行和中文行可以各写一条。书中只用作者姓的首字母指代这篇文献时（例如 `AJR (2001, 2012)`），在这一处再写 `as`：首字母缩写，照原文抄（例如 `"as":"AJR"`）；这一行必须同时写出缩写和年份。

一篇文献只出现在参考文献表里、正文没有引用时：`locations` 写 `[]`，`relations` 只写 `["背景"]`，`why` 写明「本书只在参考文献中列出这篇文献，正文没有引用它。」

## 卡片语言

全部文字遵守 `asd-ste100-zh` 技能：一句只说一件事，主动语态，不用模糊词和夸奖词。术语一律用任务文件术语表左列的写法，不用右列的词。正文里不要写 `[[…]]` 链接：链接由脚本加。

## 你的输出

把所有文献写成一个 JSON 数组，写入任务文件指定的输出文件（UTF-8），格式见任务文件末尾的样例。

## 自查

任务文件有一行 `SELF-CHECK:`，它给出 `zt-digest cited-cards -Step precheck` 命令。它按写卡时的同一套规则检查你的 JSON：每个行号都要在原文里，并且那一行（或前后一行）要提到这篇文献；关系词要在七个之内；三节的句数；术语写法。每行一个故障，格式是 `row<行号> 规则 说明`，最后一行是 `faults: N`。按故障行改正 JSON，再运行一次，直到 `faults: 0`（最多三次）。带 `(advisory)` 的行只是提示。

写完后只回复一行 JSON：`{"works":文献数,"locations":引用处总数}`
