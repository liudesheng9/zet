# 骨架任务说明

一本书（文献卡 `[[{{KEY}}]]`，ZET 代理工作区）已经消化成卡片。脚本将为它写两样东西：文献卡上的全书索引和全书的结构卡。主题树的正文不归本任务：主题树由 zt-idea-grow 从文献树长出来。脚本已经搭好框架。你只写其中的短文字，作为一个 JSON 文件。你不调用 zt，不改动任何卡片。

本说明之后附上任务文件：各组的锚点卡（标题与正文）、本书的模型卡和事件卡。**只读必须读的**：任务文件已经给出所需的全部内容，不要浏览文件夹。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）：

```json
{"chapters": [{"anchor": "{{KEY}}/1", "says": "这一组讲了什么（一句，最多 40 字）"}],
 "argument": [{"anchor": "{{KEY}}/1", "adds": "这一部分为全书论证加了什么，它怎样承接上一部分（一到两句）", "key_cards": ["{{KEY}}/1|b", "{{KEY}}/1|a"]}],
 "models": [{"address": "{{KEY}}/3|a", "shows": "这个模型说明什么（一句，最多 40 字）", "built_on_by": ["{{KEY}}/5|a"]}],
 "events": [{"address": "{{KEY}}/2|b", "supports": ["{{KEY}}/2|a"]}]}
```

- `chapters`、`argument`：每个锚点卡一项，按书中顺序。`key_cards` 选一到三张最重要的本书文献卡（只能用任务文件中出现的地址，不用主题树的卡）。
- `models`：每张模型卡一项。`built_on_by` 列出以它为基础的后面的模型卡（没有就写空列表）。
- `events`：每张事件卡一项。`supports` 列出它作为证据支持的观点卡（只用任务文件中该事件卡链接的地址）。
- 不写 `topics`：带 `topics` 的答案不通过 SELF-CHECK。
- 只用任务文件中出现的地址。不要编造地址。
- 写完文件后，运行任务文件末尾的 `SELF-CHECK` 命令（不要加 `-Apply`）。它按写入时的规则检查你的 JSON，不写任何卡片：最后一行 `"ok":true` 且 `problems` 为空才算通过。按 `problems` 改正文件，再运行一次。最多运行三次。
- 然后只回复一行 JSON：`{"chapters":数,"argument":数,"models":数,"events":数}`。

## 卡片语言

遵守 `asd-ste100-zh` 技能：一句只说一件事，描述句最多 40 字（Link 和公式不计），不用分号，主动语态，动作用动词，保留原书的语气，不用褒扬词。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
