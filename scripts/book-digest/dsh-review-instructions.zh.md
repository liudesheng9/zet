# 复核推导分卡：任务说明

你复核一个模型的一串推导分卡。别的 DeepSeek 代理已经写好了它们。你判断每张推导分卡对不对、顺不顺：有没有跳步，是不是太密、太难跟。你决定一张卡是否要拆成两张、三张或更多张，让读者一步一步跟得上。你不改卡片，只写一个结果文件。

本说明之后依次附上：模型的设定（符号表和术语表），然后是复核任务文件。任务文件给出结果文件的路径、`MaxSteps`，以及这串推导分卡的正文，还有链之前的分卡（推导从它出发）和链之后的分卡（它用推导的结果）。你需要的内容都在里面，不要读别的文件。

## 逐张检查

对每张推导分卡：

1. **对不对**：从 **起点** 出发，逐行重算 **步骤**。每一行的等式要由上一行和它写的理由得出。**结果** 要和最后一步一致。
2. **跳不跳**：一行只做一件事（代入一个式子、移一项、两边同乘、取一个极限）。一行同时做两件以上的事，或用到起点和前面步骤里都没有的事实，就是跳步。
3. **密不密**：步骤超过 `MaxSteps` 行，或者有一行长到读者要停下来自己演算，或者一张卡里出现了两个读者应该记住的中间结论，就是太密。
4. **够不够细**：读者只读这张卡和它的起点，能否在一两分钟内核对每一行。
5. **讲没讲清**：**思路** 说的路线与步骤一致吗？每行 `说明：` 解释的是读者看不出的一步吗？分情形、近似、新变量、取极限的步骤有说明吗？**解读** 由 **结果** 推得出吗？它的检验算得对吗？它有没有说出结果推不出的结论？书中没有的解释是否标了 `（补：书中未写）`？这一项有问题时判 `fix`，在 `reason` 里写出是哪一节、哪一句、应怎样改。这一项不导致 `split`。

## 判定

每张卡给一个判定：

- `ok`：正确，不跳步，不太密，讲得清。
- `fix`：有错，或有一两处跳步，补一两行就能修好，补完后不超过 `MaxSteps` 行。在 `reason` 里写清是哪一行、错在哪里、应补什么。
- `split`：太密，或补齐跳步后会超过 `MaxSteps` 行，或者含有两个以上该单独记住的中间结论。拆成 `parts` 张（2、3 或更多），每张三到六行。在 `cuts` 里按顺序给出每个切点的中间结论（式子），共 `parts - 1` 个：第一张写到 `cuts[0]`，第二张从 `cuts[0]` 写到 `cuts[1]`，……最后一张写到原来的 **结果**。切点选读者能叫出名字的中间结论。

宁可多拆一张，也不要让读者跳步。但一张三四行、每行清楚的卡不要拆。

## 结果文件

用写文件工具把一个 JSON 数组写到任务文件给出的结果文件路径（只写这一个文件），每张推导分卡一项：

```json
[
  {"address": "Key/4|a|a|3", "verdict": "ok"},
  {"address": "Key/4|a|a|4", "verdict": "fix", "reason": "第 3 行由 (5.5) 直接到 (5.7)，略去了两边同减 $K-w$；补一行。"},
  {"address": "Key/4|a|a|5", "verdict": "split", "parts": 3,
   "cuts": ["$$P=B$$", "$$B\\le L$$"],
   "reason": "九行代数含两个中间结论：先得 P=B，再得 B≤L，最后得 (5.10)。"}
]
```

`reason` 用中文，一到三句。`cuts` 里的式子用 `$$...$$`，反斜杠在 JSON 里写成 `\\`。

## 回复

写完结果文件后，只回复一行 JSON：`{"ok":1,"fix":1,"split":1}`（各判定的张数）。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
