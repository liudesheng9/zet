# 术语合并任务说明

你为一本书（文献卡 `[[{{KEY}}]]`）定稿术语表。几个探索代理各读了本书的一段，各自提出了候选术语。你把它们合并成一张表：消化这本书的代理按这张表用词，检查脚本按这张表检查每张卡片。你只写一个 JSON 文件，不调用 zt。

本说明之后附上任务文件：全部候选行（术语、不用、意思、首次定义、提出者）和结果文件的绑定字段。本书的小节原文在 `{{STAGING}}\sections\`。只在两个候选是否同一个概念、或哪个译法是原书的写法不清楚时，才用 Select-String 查原文的几行。不要通读全书。

## 怎样合并

- **同一个概念只留一行。** 几段提出同一个术语，或同一个概念的不同写法时，合成一行：术语用原书最常用、定义处用的写法；其他写法放进 `avoid`。
- **意思不同的词分开。** 原书区分的说法（例如"专用性"与"专业化"、"零利润"与"零预期利润"）各留一行，绝不能互相放进 `avoid`。拿不准时分开写，`avoid` 写空列表。
- **`avoid` 只放同一个概念的别名。** 它不能是术语本身的一部分，也不能是表里的另一个术语。
- **`meaning` 取最准确的一条**，按原书改写成一句话（最多 30 字）。
- **`section` 写最早定义它的小节号**（各段给出的小节号里最靠前的一个）。
- **删掉普通词**（"企业""价格"）和只在一段里偶然出现、没有专门意思的词。其余的候选都保留：术语的数量没有上限，按书的长度和内容决定。不要为了让表变短而删掉真正的术语。

## 工作方式

- **直接写结果文件。** 读完任务文件就合并，一次写出结果文件，再用一条命令检查它是合法的 JSON、没有重复的术语。检查通过就结束，回复状态行。
- **不写其他文件。** 不写辅助脚本、中间列表或查询结果文件；需要整理时在你自己的推理里做。
- **少查原文。** 只在两个候选是否同一个概念确实拿不准时，才用 Select-String 查原文，每次几行。
- **不做修饰。** 行的顺序、措辞的润色都不影响检查，不要为此反复改写已经合法的结果文件。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8），保留任务文件给出的全部绑定字段，只填写 `terms`：

```json
{"terms": [
  {"term": "剩余控制权", "avoid": ["剩余控制", "残余控制权"], "meaning": "契约没有写明时决定资产用法的权利", "section": "§2.1"}
]}
```

- 一个术语只出现一次（大小写不同也算同一个）。
- 写完文件后，只回复一行 JSON：`{"terms":术语数,"with_avoid":有"不用"词的术语数,"merged":合并掉的候选行数}`。

## 卡片语言

`meaning` 遵守 `asd-ste100-zh` 技能：一句只说一件事，不用分号，主动语态，保留原书的语气。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
