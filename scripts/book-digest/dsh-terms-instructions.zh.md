# 术语任务说明

你为一本书（文献卡 `[[{{KEY}}]]`）编一张术语表。消化这本书的代理按这张表用词：同一个概念始终用同一个术语，不轮换同义词。检查脚本按这张表检查每张卡片。你只写一个 JSON 文件，不调用 zt。

本说明之后附上任务文件：本书的小节标题、书中加粗的词、定义术语的句子（带小节文件和行号）。本书的小节原文在 `{{STAGING}}\sections\`。只在一个术语的意思或译法不清楚时，才用 Select-String 查原文的几行。不要通读全书。

## 选哪些词

- 选本书反复使用、有专门意思的概念：模型的名称、核心机制、关键变量的名称、作者自己定义的词。一般 20–60 个。
- 为每个术语写出"不用"的词：同一个概念的其他译法或说法，读者会误以为是另一个概念的词。例如术语 `剩余控制权`，不用 `剩余控制`、`残余控制权`。没有容易混淆的说法时，`avoid` 写空列表。
- "不用"的词必须是**同一个概念**的别名或别的译法。意思不同的词（例如"专用性"与"专业化"、"零利润"与"零预期利润"这类原书区分的说法）绝不能放进"不用"。拿不准时 `avoid` 写空列表：检查脚本会把"不用"的词当作错误，要求改写。
- "不用"的词不能是术语本身的一部分，也不能是另一个术语。
- 不选普通词（"企业""价格"），除非本书给了它专门的意思。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）：

```json
{"terms": [
  {"term": "剩余控制权", "avoid": ["剩余控制", "残余控制权"], "meaning": "契约没有写明时决定资产用法的权利", "section": "§2.1"}
]}
```

- `meaning` 用一句话（最多 30 字）说明术语的意思，按原书。
- `section` 写首次定义它的小节号。
- 写完文件后，只回复一行 JSON：`{"terms":术语数,"with_avoid":有"不用"词的术语数}`。

## 卡片语言

`meaning` 遵守 `asd-ste100-zh` 技能：一句只说一件事，不用分号，主动语态，保留原书的语气。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
