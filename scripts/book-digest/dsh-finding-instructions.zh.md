# 实证结果层任务说明

你为一本书（文献卡 `[[{{KEY}}]]`）写实证结果卡（Finding Card）。本书已经消化完：每组的观点卡和锚点卡都在 ZET 中。你只写一个 JSON 文件。脚本按它建卡、加链接。你不调用写入工具。

本说明之后附上任务文件：每组的锚点、该组写下的观点卡（地址与标题），以及"结果候选"：本组小节中报告数据、样本、调查、访谈、回归或实验，并写出数字的句子（带小节文件和行号）。原文在 `{{STAGING}}\sections\`。只在需要时用 `Select-String` 读候选句前后几行（`-Context 3,6`）。不要通读全书。

## 哪些是实证结果

- 原书报告的、由数据得出的一个结果写一张结果卡：一项调查、访谈、统计、回归、实验或案例比较得出的发现，带它的大小或方向。
- 模型的推导结论不是实证结果（它属于模型）。作者的观点、举例或文献综述里的转述，不写结果卡。拿不准时不写。
- **一卡一个结果。** 一项研究有三个结果，写三张卡。
- 结果卡只陈述结果，不解释它。解释写在链接它的观点卡里。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）：

```json
{"findings": [
  {"group": 3, "src": "sections/s05.md:41",
   "title": "31 家受访企业因为缺少保险市场推迟了投资",
   "measure": "企业推迟投资的原因。",
   "data": "48 家企业的访谈，2024 年，美国。",
   "method": "半结构访谈。",
   "result": "48 家中 31 家因为缺少保险市场推迟了投资。",
   "limits": "原因由企业自报。样本不是随机样本。",
   "section": "§3.2",
   "supports": ["Smith2024/12|a"],
   "role": "这一结果印证 [[Smith2024/12|a]] 的判断：缺少保险市场使企业推迟投资。"}
]}
```

- `title`：结果写成一句断言，带它的范围，最多 40 字。
- `measure`（测量）：研究测量了什么变量或问题。
- `data`（数据）：样本、时期和地点。原书没有给出的项写 `原书未写明`，不要编造。
- `method`（方法）：访谈、调查、回归、实验、案例比较等。
- `result`（结果）：一个结果，写出它的大小或方向。只写一句或一条，不列多项。
- `limits`（局限）：这个结果不能说明什么：样本、自报、识别等。原书没有说明时写 `原书未写明`。
- `section`：结果所在的小节号，例如 `§3.2`。
- `supports`：这个结果作为证据支持的观点卡，必须是任务文件里该组列出的卡片。脚本让每张支持的卡都链接结果卡（关系词 `印证`）。
- `role`：一句话，以 `这一结果印证 [[地址]]` 开头，地址取自 `supports`。
- 一组没有实证结果时，不为它写任何条目。

结果卡放在该组锚点的侧后继上。脚本写出它的正文：

```
测量：……
数据：……
方法：……
结果：……
局限：……
来源：[[{{KEY}}/n]] §…

这一结果印证 [[观点卡]] 的判断：……
```

## 自查

写完文件后运行任务文件里的 `SELF-CHECK` 命令。它按建卡时的同一套规则检查你的草稿（包括 F1 标签、F2 来源、F3 一卡一个结果和卡片语言），每行一个问题，最后一行是 `faults: N`。改到 `faults: 0` 为止，最多运行三次。

## 回复

只回复一行 JSON：`{"findings":结果卡数}`。

## 卡片语言

所有文字遵守 `asd-ste100-zh` 技能：一句只说一件事，描述句最多 40 字，不用分号 `；`，主动语态，保留原书的语气（原书说"可能"就写"可能"）。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
