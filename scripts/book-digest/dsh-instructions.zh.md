# 任务说明（所有组共用）

你负责把《{{TITLE}}》（文献卡 `[[{{KEY}}]]`，位于 ZET 代理工作区的文献区）中分配给你的小节消化为 ZET 卡片。按已加载的 `zettelkasten` skill 撰写、放置和链接卡片。全部卡片用中文。本说明之后只附上你的组信息和你的小节原文；全书其他部分和现有卡片都在磁盘上，按需自己读取，不要通读全书。

## 磁盘上的资料（只读，不要修改）

- **全书索引** `{{INDEX}}`：每个小节文件对应的章节、所属组和锚点卡片。很短，先读它。
- **小节文件** `{{STAGING}}\sections\sNN.md`；合并全文 `{{STAGING}}\book.zh.md`。
- **现有主题卡片快照**：组信息中给出的 snapshot 文件，列出所有主题树卡片的地址和标题（代理与人类工作区）。
- **双语原文** `{{SOURCE}}`：只在需要核对英文原文时读取相关段落。
- 卡片正文：需要时用助手脚本的 `get_card` 或 `search_cards` 读取。

先搜索、再精读：用 `Select-String -Path "{{STAGING}}\sections\*.md" -Pattern '敲竹杠|剩余控制权' | Select-Object -First 15` 找出某个概念出现在哪些小节，再只打开最相关的一到三处（`-Context 2,4` 往往就够），不要整份读入。

## 步骤（全程最多 4 条命令）

1. **探索（一条命令）**：在同一条 pwsh 命令里读快照，并对你这部分的 3–5 个核心概念做 `Select-String`。组信息里已列出用词最接近的其他小节，先从它们看起；全书索引只在需要时读。
2. **精读（可选，一条命令）**：只读上一步找到的最相关段落（`-Context` 或 `Get-Content` 的行范围），弄清你的小节承接哪些部分、被哪些部分用到。
3. **写入（一条命令）**：写完全部卡片并改写锚点；失败时按 resume 行重跑算作第 4 条。
4. **回复**一行 JSON。

每多一条命令都会重读整个对话，所以把读取合并起来，不要逐个文件、逐张卡片地读写，也不要为确认写入结果再读一遍。

## 写入 ZET

你没有原生 zt 工具。用一条 pwsh 命令把全部调用通过 here-string 交给助手脚本（`'@` 必须单独占一行、顶格），命令末尾照抄组信息中的 `-Log` 参数，它记录你写的卡片：

```
@'
[{"tool":"create_topic","arguments":{"title":"剩余控制权","body":"……"}},
 {"tool":"create_successor","arguments":{"at":"@@0","title":"……","body":"……"}},
 {"tool":"create_successor","arguments":{"at":"{{KEY}}/7","kind":"side","title":"……","body":"…… [[@@1]] ……"}},
 {"tool":"edit_card","arguments":{"at":"{{KEY}}/7","title":"……","body":"……"}}]
'@ | pwsh -NoProfile -File "{{HELPER}}" - -Log "…"
```

- 字符串参数中的 `@@N` 替换为第 N 个调用（从 0 起）返回的地址，只能指向**更早**的调用：先建被链接的卡片，再建链接它的卡片；互相链接时最后用 `edit_card` 补回指。
- 输出每行一条：`N ok <地址>`；失败为 `N error <原因>` 并停止，随后一行 `resume: -From N -Addresses …`。只修改第 N 个调用，用同一 here-string 重跑，并在命令末尾加上这两个参数；已成功的调用不会重复执行。
- 工具：`create_topic`（title, body）、`create_successor`（at, title, body, kind: direct|side, type: idea|event|model）、`edit_card`（at, title, body, type）；读取用 `get_card`（at）、`search_cards`（query, limit）。人类工作区只读，可以链接。不要删除或移动卡片。
- `body` 只写正文，不要以 `# 标题` 开头。

## 放置

- 同一概念已有主题时，把卡片挂到快照中最贴切的卡片下：作为直接后继（该卡的直接后继槽空着、且你的卡是论证的下一步）或侧后继（其余情况）。判断直接后继槽是否已占用：以数字结尾的地址末位加一（`12/1|a|1` → `12/1|a|2`），以字母结尾的地址末尾加 `|1`（`12/1|a` → `12/1|a|1`）；快照中已有该地址即已占用。
- **主题树卡片**（多数卡片放这里）：脱离本书也能成立的观点。没有合适主题时才 `create_topic`（主题名为概念名，正文 2–3 句说明追问的问题），再于 `<n>/0` 建首卡。
- **文献树卡片**：只依附于本书论证的笔记（模型设定、推导步骤、作者对文献的评述），放在你的锚点的侧后继（`kind: side`）及其直接后继上。只在你的锚点下建文献树卡片。
- **最后改写你的锚点**（`edit_card`）：标题为这一部分的核心论点（一句话断言）；正文为小节索引，每行 `§2.1 - 该节讲了什么`，再用带理由的句子链接本组最重要的 3–6 张卡片，最后一段以"在全书中的位置："开头，用 2–4 句说明本部分承接哪些部分、引出哪些部分，并链接相应锚点卡片。

## 事件卡与模型卡

按 skill 中的"Event Cards and Model Cards"一节撰写，用 `create_successor` 的 `"type"` 参数标明类型：

- **模型卡**（`"type":"model"`）：你的小节提出的每个完整模型（形式模型，或有明确假设的概念模型）写一张，放在你的锚点下作侧后继，且在批处理中**排在讨论它的卡片之前**。正文依次为：问题；设定；假设；时序与信息；求解或均衡；主要结论；直觉；局限；来源（写明小节号，如 `来源：[[{{KEY}}]] §2.2`）。可写到 600 字左右。每个模型只写这一张完整的模型卡：本组结束后，会有专门的阶段对照原文核实它，自行决定模型的结构（需要哪些模型分卡、各自叫什么、谁依赖谁、哪些是核心），并配上图表，所以你**不要**传 `facet` 或 `emphasis`，也不要自己拆分。
- **讨论模型的卡片**（推导、结论、解释、推广、批评，不论放在文献树还是主题树）**都必须链接该模型卡**，并说明涉及模型的哪一部分：`在 [[@@0]] 的设定下，……`。模型若由其他组提出，链接其锚点或快照中的模型卡。
- **事件卡**（`"type":"event"`）：原书报告的真实发生、有时间的事件（收购、立法、判例、破产、危机等）写一张；模型里的假想例子不是事件。标题为带时间的一句话事件；正文写清何事、何时何地、谁、来源，不加解释，最后一段说明它是哪些观点的证据并链接。放在它最先支持的观点卡旁（侧后继）或你的锚点下；用到它的观点卡都链接它。

## 卡片规则

- 一卡一观点；标题为一句完整断言；用自己的话，不抄译文；可独立理解；正文约 80–200 字；公式用 `$...$`。
- 每张卡在说明关系的句子中至少链接一张父卡以外的卡片（支持、反驳、限定、举例、同一机制见于别处、定义）。
- **跨部分链接**：至少一半的卡片链接全书**其他部分**（索引中其他组的锚点卡，或快照中其他章节的卡片），并写出逻辑链：`承接 [[{{KEY}}/6]]：正因为……，所以本节……`、`第 7 章 [[{{KEY}}/22]] 把同一机制用于破产：……`。只说"相关"不算。尚未写出的部分可以链接其锚点卡。
- 来源行：`来源：[[{{KEY}}]] §2.2`。
- 本组约写 6–12 张卡，宁少而精。
