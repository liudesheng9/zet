# 任务说明（所有组共用）

你负责把《{{TITLE}}》（文献卡 `[[{{KEY}}]]`，位于 ZET 代理工作区的文献区）中分配给你的小节消化为 ZET 卡片。按已加载的 `zettelkasten` skill 撰写、放置和链接卡片。全部卡片用中文。本说明之后只附上你的组信息和你的小节原文；全书其他部分和现有卡片都在磁盘上，按需自己读取，不要通读全书。

## 磁盘上的资料（只读，不要修改）

- **全书索引** `{{INDEX}}`：每个小节文件对应的章节、所属组和锚点卡片。很短，先读它。
- **小节文件** `{{STAGING}}\sections\sNN.md`；合并全文 `{{STAGING}}\book.zh.md`。
- **现有主题卡片快照**：组信息中给出的 snapshot 文件，列出所有主题树卡片的地址和标题（代理与人类工作区）。
- **双语原文** `{{SOURCE}}`：只在需要核对英文原文时读取相关段落。
- 卡片正文：需要时用助手脚本的 `get_card` 或 `search_cards` 读取。

先搜索、再精读：用 `Select-String -Path "{{STAGING}}\sections\*.md" -Pattern '敲竹杠|剩余控制权' | Select-Object -First 15` 找出某个概念出现在哪些小节，再只打开最相关的一到三处（`-Context 2,4` 往往就够），不要整份读入。

## 步骤（全程最多 7 条命令）

1. **探索（一条命令）**：在同一条 pwsh 命令里读快照，并对你这部分的 3–5 个核心概念做 `Select-String`。组信息里已列出用词最接近的其他小节，先从它们看起；全书索引只在需要时读。
2. **精读（可选，一条命令）**：只读上一步找到的最相关段落（`-Context` 或 `Get-Content` 的行范围），弄清你的小节承接哪些部分、被哪些部分用到。
3. **写入（一条命令）**：写完全部卡片并改写锚点；失败时按 resume 行重跑算作一条。
4. **自查（一条命令）**：运行组信息里的 `SELF-CHECK` 命令。它列出你的卡片和锚点的每个问题，每行一个：地址、规则号、句子，最后一行是 `faults: N`。
5. **修正（可选）**：有问题时，用一条写入命令改正全部问题（`edit_card`），再运行一次 `SELF-CHECK`。
6. **回复**一行 JSON。

自查命令是 `zt-check`：它按检查阶段的同一套规则检查你写的卡片，不改任何卡片。你不必猜哪些写法合规：改到它报告 `faults: 0` 为止。最多运行三次。三次后仍有问题，照常回复，并在 `errors` 里写出剩下的问题。

每多一条命令都会重读整个对话，所以把读取合并起来，不要逐个文件、逐张卡片地读写，也不要为确认写入结果再读一遍。

## 写入 ZET

你没有原生 zt 工具。用一条 pwsh 命令把全部调用通过 here-string 交给助手 `zt-digest call`（`'@` 必须单独占一行、顶格），命令末尾照抄组信息中的 `-Log` 参数，它记录你写的卡片：

```
@'
[{"tool":"create_topic","arguments":{"title":"剩余控制权","body":"……"}},
 {"tool":"create_successor","arguments":{"at":"@@0","title":"……","body":"……"}},
 {"tool":"create_successor","arguments":{"at":"{{KEY}}/7","kind":"side","title":"……","body":"…… [[@@1]] ……"}},
 {"tool":"edit_card","arguments":{"at":"{{KEY}}/7","title":"……","body":"……"}}]
'@ | zt-digest call - -Log "…"
```

- 字符串参数中的 `@@N` 替换为第 N 个调用（从 0 起）返回的地址，只能指向**更早**的调用：先建被链接的卡片，再建链接它的卡片；互相链接时最后用 `edit_card` 补回指。
- 输出每行一条：`N ok <地址>`；失败为 `N error <原因>` 并停止，随后一行 `resume: -From N -Addresses …`。只修改第 N 个调用，用同一 here-string 重跑，并在命令末尾加上这两个参数；已成功的调用不会重复执行。
- 工具：`create_topic`（title, body）、`create_successor`（at, title, body, kind: direct|side, type: idea|event|model, level: concept|formal）、`edit_card`（at, title, body, type, level）；读取用 `get_card`（at）、`search_cards`（query, limit）。人类工作区只读，可以链接。不要删除或移动卡片。
- **来源位置**：每个 `create_successor` 调用加一个 `src` 字段，写出这张卡依据的小节文件和行号，例如 `"src":"sections/s05.md:120-160"`。不确定行号时只写文件（`"sections/s05.md"`）。助手脚本把它记入来源日志，不写进卡片；检查阶段按它对照原文核实卡片。
- **主题闸门**：`create_topic` 可能被拒绝：`N error topic exists: 12/0 剩余控制权……`。这说明已有同名或几乎同名的主题。把这次调用改为挂在那个主题下的 `create_successor`（不要换个名字再建主题），按 resume 行重跑。
- `body` 只写正文，不要以 `# 标题` 开头。

## 放置

- 同一概念已有主题时，把卡片挂到快照中最贴切的卡片下：作为直接后继（该卡的直接后继槽空着、且你的卡是论证的下一步）或侧后继（其余情况）。判断直接后继槽是否已占用：以数字结尾的地址末位加一（`12/1|a|1` → `12/1|a|2`），以字母结尾的地址末尾加 `|1`（`12/1|a` → `12/1|a|1`）；快照中已有该地址即已占用。
- **主题树卡片**（多数卡片放这里）：脱离本书也能成立的观点。没有合适主题时才 `create_topic`（主题名为概念名，正文 2–3 句说明追问的问题），再于 `<n>/0` 建首卡。
- **文献树卡片**：只依附于本书论证的笔记（模型设定、推导步骤、作者对文献的评述），放在你的锚点的侧后继（`kind: side`）及其直接后继上。只在你的锚点下建文献树卡片。
- **最后改写你的锚点**（`edit_card`）：标题为这一部分的核心论点（一句话断言）；正文为小节索引，每行 `§2.1 - 该节讲了什么`，再用带理由的句子链接本组最重要的 3–6 张卡片，最后一段以"在全书中的位置："开头，用 2–4 句说明本部分承接哪些部分、引出哪些部分，并链接相应锚点卡片。

## 事件卡与模型卡

按 skill 中的"Event Cards and Model Cards"一节撰写，用 `create_successor` 的 `"type"` 参数标明类型：

- **模型卡**（`"type":"model"`）：你的小节提出的每个完整模型（形式模型，或有明确假设的概念模型）写一张，并用 `"level"` 标明它的**细化层级**（见下条），放在你的锚点下作侧后继，且在批处理中**排在讨论它的卡片之前**。正文依次为：问题；设定；假设；时序与信息；求解或均衡；主要结论；直觉；局限；来源（写明小节号，如 `来源：[[{{KEY}}]] §2.2`）。可写到 600 字左右。每个模型只写这一张完整的模型卡：本组结束后，会有专门的阶段对照原文核实它，自行决定模型的结构（需要哪些模型分卡、各自叫什么、谁依赖谁、哪些是核心），并配上图表，所以你**不要**传 `facet` 或 `emphasis`，也不要自己拆分。
- **细化层级**（`level`）：
  1. `"formal"`（第 2 层，形式模型）：原书用数学给出模型，即有符号、方程、推导、带证明的命题，或要靠代数算出的数值例子。模型阶段会把它建成自足模型，补上书中略去的推导步骤。
  2. `"concept"`（第 1 层，概念模型）：原书用文字或示意图给出模型，即一个机制、一个分类、一个框架或一段文字论证。原书只引用或概述一个形式模型而不推导它，也算概念模型。模型阶段只核实它，不加推导分卡。
  拿不准时写 `"formal"`，模型阶段会复核。
- **讨论模型的卡片**（推导、结论、解释、推广、批评，不论放在文献树还是主题树）**都必须链接该模型卡**，并说明涉及模型的哪一部分。ZET 从 Link **紧前的词**读出关系类型，所以把关系词写在 Link 前：推导或用到它写 `依赖 [[@@0]] 的设定：……`，举例或应用写 `例示 [[@@0]]：……`，推广或放宽假设写 `放宽 [[@@0]] 的……假设：……`，比较写 `对照 [[@@0]]：……`，类比写 `对应 [[@@0]]：……`，批评写 `反驳 [[@@0]]：……`。模型若由其他组提出，链接其锚点或快照中的模型卡。
- **事件卡**（`"type":"event"`）：原书报告的真实发生、有时间的事件（收购、立法、判例、破产、危机、公司重组等）写一张；模型里的假想例子不是事件，引用某篇文献的年份也不是事件。组信息列出了"事件候选"：本组小节中写出年份的句子，先看它们。标题为带年份的一句话事件（`1926 年通用汽车收购费雪车身公司`）。正文用下面的固定格式，检查脚本按这些标签检查；原书没有给出的项写 `原书未写明`，不要编造：

  ```
  时间：……
  地点：……
  参与者：……
  经过：……（只写发生了什么，不加解释）
  来源：[[{{KEY}}]] §n

  证据作用：本事件例示 [[观点卡]] 的……
  ```

  写事件卡前先 `search_cards`（`"type":"event"`，用事件的主角或年份查询）：同一事件已有事件卡时（别的书也可能报告过它），不要再写一张，用 `edit_card` 在那张卡的 `来源：` 行后追加本书的来源和证据作用，并让你的观点卡链接它。放在它最先支持的观点卡旁（侧后继）或你的锚点下；用到它的观点卡都链接它，关系词写 `例示` 或 `案例`。

## 书中的图

原文里形如 `![图 2.C.1](artifact:…)` 的一行是书中的原图。ZET 已保存这张图，卡片可以直接显示它。它后面常跟着英文图注（`Figure 2.C.1 (left)`）。

- 卡片讲到某张图（`图 2.C.1 画出……`、`如图所示`）时，把这一行**原样**复制进卡片正文，单独成段，放在第一次提到它的那段之后。不要改动 `artifact:` 后面的 64 位地址，也不要自己编造地址。
- 一张图只放进最需要它的卡片：通常是解释这张图的卡片。其他卡片写 `见图 2.C.1`，并链接那张卡片。
- 不要为书中已有的图另画示意图表。书中没有的图才用图表画。
- 原文里没有 `artifact:` 行的图（版式装饰、题号小图）不放进卡片。

## 卡片语言

标题和正文遵守 ASD-STE100（简化技术英语）改写成的中文规则。经理已通过 `skills` 把 `asd-ste100-zh` 技能交给你：先按该技能写。下面是本项目的具体上限，与技能中的数字不同时，以下面为准（检查脚本按这些数字检查）。公式、链接、图表代码和书中原话不受限制。

1. 一句只说一件事：`E 违约。C 清算资产。`，不写 `E 违约，于是 C 清算资产，同时……`。
2. 描述句最多 40 字（公式和链接不计）。在每个新陈述处断句。
3. 不用分号 `；`，写成两句。
4. 主动语态，写出动作者：`C 清算资产。`，不写 `资产被清算。`（书中没有写出动作者时才用"被"）。
5. 动作用动词：`分析`、`决定`，不写 `进行分析`、`作出决定`。
6. 一个术语一个意思：同一个概念始终用同一个词，不轮换同义词。组信息给出本书的术语表 `terms.md` 时，用表中的术语，不用"不用"列的词（检查脚本按此表检查）。
7. 一个名词短语最多两个"的"。
8. 保留原书的语气：原书说"可能"就写"可能"。
9. 不堆叠限定，不用褒扬词：不写 `值得注意的是`、`在某种程度上`、`精妙`、`深刻`。
10. 三个以上的步骤或条件用编号列表。
11. 标题只陈述一个论断，最多 40 字。
12. 卡片要独立可读：标题和正文里不用本书的编号代替内容（`式 (12)`、`命题 3.G.3`、`第 6 章`、`模型 1`、`本节`、`§11.D`）。写出编号所指的公式、命题、模型或步骤本身；编号可以作为次标签留在后面。`第一福利定理` 这类有名字的结论不算编号。
13. 不写没有名字的指代：`那里`、`该卡`、`那张卡`。写出它指的是哪个概念、模型或结论；需要时把 Link 放进同一句。前一句里的名字不算。
14. 主题树的观点卡要自足：正文写出它依赖的必要条件或假设本身，不靠在本书文献树上的 `依赖 [[{{KEY}}/n]]` 成立。要用本书的材料，改用真实的关系：`例示`、`对应`、`对照`，或把这张卡放进文献树。只把 `依赖` 换成 `对应` 不算改好。

**模型卡写出完整的设定。** 写明参与者、时序、信息和全部符号的含义。不要写 `沿用某模型的设定` 而不写出设定：读者只读这张模型卡，也要知道模型的前提。

## 卡片规则

- 一卡一观点；标题为一句完整断言；用自己的话，不抄译文；可独立理解；正文约 80–200 字；公式用 `$...$`。
- 每张卡在说明关系的句子中至少链接一张父卡以外的卡片（支持、反驳、限定、举例、同一机制见于别处、定义），关系词尽量紧贴在 Link 前（`依赖`、`例示`、`对照`、`放宽`、`对应`、`反驳`）。
- **跨部分链接**：至少一半的卡片链接全书**其他部分**（索引中其他组的锚点卡，或快照中其他章节的卡片），并写出逻辑链：`承接 [[{{KEY}}/6]]：正因为……，所以本节……`、`第 7 章 [[{{KEY}}/22]] 把同一机制用于破产：……`。只说"相关"不算。尚未写出的部分可以链接其锚点卡。
- 来源行：`来源：[[{{KEY}}]] §2.2`。
- 本组约写 6–12 张卡，宁少而精。
