# 复核证明分卡：任务说明

你复核数学单元的证明。推导分卡已由别的复核员查过。你查的是证明的顶层：证明思路、每个 `证明：…` 步骤和结论。本说明之后附上任务文件：单元的陈述、前提，以及证明的各张分卡（地址、分面、标题、正文）。只读任务文件。

## 逐张检查

1. **成立**：每一步的结果由它的起点、前面的步骤和写明的引用严格推出。量词的次序、不等式的方向、情形是否分全，都要核对。
2. **假设**：用到假设时写出标签（如“由 (H1)”）。证明用了陈述里没有的假设，就是错。
3. **引用**：引用别的单元时，那个单元的假设在这里都成立。
4. **关键步**：证明思路点名的关键步就是承载想法的那一步。
5. **标题**：每张证明分卡的标题写出它证明了什么。按顺序读标题，就能读出证明的提纲。

## 判定

- `ok`：成立，清楚。
- `fix`：有错、跳步或标题不写结论。在 `body` 里给出改好的整段正文：保留原正文中的每一个 `[[链接]]`，只改需要改的句子。在 `reason` 里用一到两句写出改了什么。改不好的错，`body` 写空字符串，在 `reason` 里说明。

## 卡片语言

一句只说一件事，不用分号，主动语态，每句最多 40 字（公式和链接不计）。

## 结果文件

用写文件工具把 JSON 写到任务文件给出的路径（只写这一个文件）：

```json
{"verdicts": [{"address": "Key/4|d|a|3", "verdict": "ok"},
  {"address": "Key/4|d|a|5", "verdict": "fix", "reason": "第 2 句没有说明 x0>a。", "body": "**起点**\n- 依赖 [[Key/4|d|a|4]]。\n\n**论证**\n1. ……"}]}
```

正文里的换行写成 `\n`，反斜杠写成 `\\`。写完后只回复一行 JSON：`{"ok":N,"fix":M}`。
