
# 填写数学单元（补充）

上面的填写说明全部照常有效。任务所属的模型卡带 `form`（数学单元）时，另守本节。两处冲突时，以本节为准。

## 命令数

一个任务写一个数学单元的全部分卡时，命令预算与上面的填写说明相同：最多 8 条。先分几条命令写完各分卡，最后用一条 `zt-check` 列出任务文件的每一张分卡。

## 单元的模型卡

任务写“要写：问题、概要……”时，单元的模型卡改写为下面几节：

- **动机**（代替“问题”）：一到三句，这个单元回答什么问题。
- 结果写 **陈述**（代替“概要”）：每个假设一行，以 `(H1)`、`(H2)` 开头，最后一行 `结论：……`。定义写 **定义**，每个条款一行，以 `(C1)`、`(C2)` 开头。
- 结果写 **思路**：只写一句，说出证明的关键想法。证明思路分卡写其余内容，模型卡不重复它。
- **结构**、**关联**、**来源** 照常。

## 分卡的分面与内容

| 分面 | 写什么 |
| --- | --- |
| `前提` | 证明用到的对象、全部假设（带标签）和符号。骨架里的符号表原样保留。 |
| `证明思路` | 方法（直接、反证、逆否、归纳、构造、分情形或对角线）、关键想法、关键步的名字，以及顶层步骤的编号列表。 |
| `证明：…` | 一个顶层步骤。标题写这一步证明了什么。正文按推导分卡的次序写：**思路**（这一步走哪条路，一到三句）、**起点**（依赖哪些前面的分卡）、**论证**（编号的几句推理，每句写理由，用到假设时写标签，如“由 (H1)”，读者不能一眼看出的一句下面加一行 `说明：……`）、**结果**。关键步另写 **解读**：这一步为什么是整个证明的关键。 |
| `推导：…` | 照上面推导分卡的写法。 |
| `结论` | 把各步合起来，说明定理成立。 |
| `直觉`、`图示` | 为什么结论应当成立。用文字，或用图表画出来。 |
| `例子` | 一个满足定义或定理的具体对象，写出验证它的计算。 |
| `非例` | 一个只违反一个条款的对象。写明违反的是哪个条款，例如“(C2) 不成立”。 |
| `反例：…` | 一个对象，说明去掉某个假设或换成逆命题后结论不成立。链接它否定的单元：`反例 [[单元]]：……` |
| `假设作用：Hi` | 假设 Hi 在哪一步用到，去掉它会怎样。链接那一步和对应的反例。 |
| `等价刻画` | 链接证明等价的结果：`对应 [[结果]]`。 |
| `另证` | 第二种证明，写法同证明。 |
| `习题` | 题目。答案写在 `## 答案` 之下。原书没有答案时，不写答案。 |
| `历史` | 谁、为什么提出它。 |

## 引用别的单元

证明用到别的定理、引理、定义时，链接那个单元的**模型卡**，写 `依赖 [[单元]]` 或 `按定义 [[单元]]`。不要链接另一个单元的证明分卡（伸入）。任务文件给出被引单元的地址。

## 补写的内容

原书没有给出、你自己补写的例子、非例、反例，正文末尾标 `（补：书中未给）`。补写的推理步骤照常标 `（补：书中略去）`。补写的对象必须真的满足（或违反）所说的条件。拿不准就不写，回复 `blocked` 并写明原因。
