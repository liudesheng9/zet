# 术语卡任务说明

你为一本书（文献卡 `[[{{KEY}}]]`）的术语写术语卡的内容。每个术语一张卡。读者是刚入门的研究者：他要从这张卡真正学会这个术语，包括它的数学。你只写一个 JSON 文件，不调用 zt，不写卡片的 Markdown 排版。

本说明之后附上任务文件：本次的术语（术语、不用的词、一句话意思、首次定义的小节）、每个术语的定义句（带小节文件和行号）、术语出现的小节文件、本书的其他术语、数学任务还附上本书的符号表。本书的小节原文在 `{{STAGING}}\sections\`。先读定义句所在的几行，再按需读术语出现的段落。不要通读全书。

## 每个术语写什么

- `explanation`：3–8 句。说清术语指什么、用来做什么、本书怎么用它。不懂数学的读者也能读懂这一部分。
- `book_definition`：本书自己的定义，用 1–4 句转述，写明小节。可以引用原文最多一句，放在「」里。
- `category`：`concept`（概念）或 `math`（数学概念）。任务文件给出初始分类和依据；你读过原文后，如果术语有公式定义、或本书用公式推导它的性质，就写 `math`，并按下面的数学要求写全。初始分类是概念而实际是数学概念的，必须写全数学部分；这种术语会单独审查。
- `link`：通常写 `true`。只有术语是极常用的词、在正文里链接它没有帮助时，写 `false`，并在 `link_reason` 里说明。
- `first_defined`：首次定义的小节号，按任务文件给的写法。

## 数学概念：尽可能详细

`category` 为 `math` 时，下面每一项都要写全：

1. `hypotheses`：每个前提一条，编号 H1、H2……。写明每个对象在哪个集合里、函数可微几次、哪些参数为正。
2. `definition`：定义写成一个展示公式，加标签 `\tag{T1}`；再用 1–3 句把公式读出来。
3. `symbols`：公式里出现的每个符号都列出：符号、含义、类型与取值。用本书的符号。你新引入的辅助符号标 `"auxiliary": true`。
4. `equivalent_forms`：本书或标准文献里的等价写法，每个写一句理由，说明它为什么等于 (T1)。
5. `derivations`：每个推导一节，写明推导什么（`claim`）。每一步只做一个变换，写出变换后的式子，并写明依据（链式法则、取对数、一阶条件、隐函数定理、代入 (T1)、同步骤 k……）。不跳过代数。不写「易知」「显然」「不难看出」。最后写 `result`，它必须正好是 `claim`。一节最多 {{MAX_STEPS}} 步；更长的推导拆成几节。
6. `limits`：有极限情形或特例时逐一写出，每个带公式。
7. `example`：一个数值例子，用小的数，每个数都在文中算出来，读者能用计算器重算。
8. `intuition`：2–5 句直觉。
9. `misreadings`：学生容易犯的误读，以及为什么错。

写完推导后，自己逐步核对。可以在工作目录里用一个短脚本数值验证某一步；没有运行过的验证不要声称运行过。

## 所有术语都写

- `distinctions`：与本书其他相近术语的区别，每条写对方术语的**原名**（照任务文件里的写法）和 1–2 句区别。
- `role_in_book`：1–4 句，本书哪些结论依赖这个术语。
- 概念术语不写 `数学定义`、`等价形式`、`推导`、`极限与特例` 这些数学部分；写了就是错误。

## 卡片语言

全部文字遵守 `asd-ste100-zh` 技能：一句只说一件事，不用分号，主动语态，不用模糊词和夸奖词。术语一律用任务文件里的写法，不用「不用」栏里的词。公式用 LaTeX，行内 `$…$`，展示 `$$…$$`。正文里不要写 `[[…]]` 链接：链接由脚本加。正文总长不超过 {{MAX_PROSE}} 个字符（数学公式和表格不算）。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8），格式见任务文件末尾的样例。

## 自查

任务文件有一行 `SELF-CHECK:`，它给出这个任务的 `zt-digest term-cards -Step precheck` 命令。它按脚本写入卡片时的同一套规则检查你的 JSON 文件，不写任何卡片：每行一个故障，格式是 `临时地址 规则 说明`，最后一行是 `faults: N`。按故障行改正 JSON，再运行一次，直到 `faults: 0`（最多三次）。带 `(advisory)` 的行只是提示，不计入 `faults`。

写完后只回复一行 JSON：

`{"terms":术语数,"math":数学概念数,"steps":推导总步数}`

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
