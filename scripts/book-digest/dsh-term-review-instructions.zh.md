# 术语卡审查与修正说明

你审查一张数学术语卡草稿（JSON），把找到的错误直接改好，再交出改好的草稿。审查和修正都由你在这一个对话里完成。

## 你要读的文件

- 任务文件（审查请求）：术语、草稿内容和你的答案文件路径。
- 写卡说明 `dsh-term-card-instructions.zh.md`：草稿的格式和写卡规则。改草稿时遵守它。
- 写卡任务文件 `jobs\<任务>.md`：草稿文件的路径（「只写一个 JSON 文件」那一行）、原文行和 `SELF-CHECK:` 自查命令。

## 第一步：审查

逐项核对，记下每一处错误：

1. 前提。推导用到的前提都列出了吗。
2. 定义。定义公式 (T1) 与本书一致吗。读任务文件给出的原文行。
3. 符号。公式里的符号都在符号表里吗。
4. 推导。每一步真的从上一步得到写出的式子吗。逐步代数核对。
5. 结论。`result` 与 `claim` 一致吗。
6. 极限与特例。说法正确吗。
7. 数值例子。重算每个数。
8. 补充标记。书中没写、由写卡人补上的步骤标了 `（补：书中略去）` 或 `（补：书中未写）` 吗。

## 宽严标准

只有让读者学错东西的错误才是错误：公式、推导步骤、数值或结论算错了，与本书原文矛盾，或推导依赖一个没有列出的前提。

下面这些不算错误，看到就顺手改好，不要因为它们拒绝：措辞和语气、小节号或行号标错、符号表少列一个符号、缺补充标记、类型写得不够精确、深度和详略、排版。

## 第二步：修正

有错误时，在草稿文件里直接改正，只改有错的地方，其余内容保持原样。改完运行写卡任务文件里的 `SELF-CHECK:` 命令，按故障行改正，直到最后一行是 `faults: 0`（最多三次）。

## 你的答案

只写任务文件指定的答案文件，UTF-8，一个 JSON 对象：

- 草稿原来就对，或你已改好且自查 `faults: 0`：`{"ok":true,"fixed":改正的处数}`
- 有一处你改不好的错误（例如推导本身不成立、你找不到本书依据）：`{"ok":false,"faults":[{"where":"derivations[0].steps[4]","what":"一句话说错在哪","fix":"一句话说该怎么改"}]}`

只列你改不好的错误。你不声称做过没有做的检查。

最后只回复一行 JSON：`{"ok":true或false,"fixed":改正的处数}`
