# 事件层任务说明

你为一本书（文献卡 `[[{{KEY}}]]`）写事件卡。本书已经消化完：每组的观点卡、模型卡和锚点卡都在 ZET 中。你只写一个 JSON 文件。脚本按它建卡、加链接。你不调用写入工具。

本说明之后附上任务文件：每组的锚点、该组写下的观点卡（地址与标题），以及"事件候选"：本组小节中写出年份的句子（带小节文件和行号）。原文在 `{{STAGING}}\sections\`。只在需要时用 `Select-String` 读候选句前后几行（`-Context 2,4`）。不要通读全书。

## 哪些是事件

- 原书报告的真实发生、有时间的事件写一张事件卡：收购、立法、判例、破产、危机、公司重组等。
- 模型里的假想例子不是事件。引用某篇文献的年份也不是事件。拿不准时不写。
- 一个事件只写一次。写之前查重：用助手脚本读已有事件卡（只读），例如：

  ```
  @'
  [{"tool":"search_cards","arguments":{"type":"event","query":"通用汽车"}}]
  '@ | zt-digest call -
  ```

  同一事件已有事件卡时（别的书也可能报告过它），在 `existing` 写那张卡的地址。脚本在它的来源行后追加本书的来源和证据作用，不再建新卡。

## 你的输出

把结果写入任务文件指定的 JSON 文件（UTF-8）：

```json
{"events": [
  {"group": 3, "src": "sections/s05.md:41",
   "title": "1926 年通用汽车收购费雪车身公司",
   "time": "1926 年", "place": "美国", "actors": "通用汽车、费雪车身公司",
   "course": "通用汽车买下费雪车身公司的全部股份。",
   "section": "§3.2",
   "supports": ["Smith2024/12|a"],
   "role": "本事件例示 [[Smith2024/12|a]] 的论点：纵向一体化消除敲竹杠。",
   "existing": ""}
]}
```

- `title`：带年份的一句话事件，最多 40 字。
- `time`、`place`、`actors`、`course`：原书没有给出的项写 `原书未写明`，不要编造。`actors` 用顿号分隔。`course` 只写发生了什么，不加解释。
- `section`：事件所在的小节号，例如 `§3.2`。
- `supports`：这个事件支持的观点卡，必须是任务文件里该组列出的卡片。第一张是事件卡放置的位置（作它的侧后继）。脚本让每张支持的卡都链接事件卡（关系词 `案例`）。
- `role`：证据作用，一句话，以 `本事件例示 [[地址]]` 开头，地址取自 `supports`。
- `existing`：已有同一事件的事件卡时写它的地址，否则写空字符串。
- 一组没有真实事件时，不为它写任何条目。

## 自查

写完文件后运行任务文件里的 `SELF-CHECK` 命令。它按建卡时的同一套规则检查你的草稿，每行一个问题，最后一行是 `faults: N`。改到 `faults: 0` 为止，最多运行三次。

## 回复

只回复一行 JSON：`{"events":事件数,"existing":已有事件卡数}`。

## 卡片语言

`title`、`course` 和 `role` 遵守 `asd-ste100-zh` 技能：一句只说一件事，描述句最多 40 字，不用分号 `；`，主动语态，保留原书的语气。

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
