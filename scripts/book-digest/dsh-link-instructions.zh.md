## 步骤

1. **核实（一条命令）**：读任务文件和缺口清单，用 `get_card` 一次读出你打算链接的候选卡片正文，确认关系成立。
2. **写草稿**：把结果写入任务文件给出的 JSON 路径（UTF-8）。只写这一个文件。
3. **自查**：原样复制任务文件里的 `SELF-CHECK:` 行运行（`zt-digest link-finish ... -CheckOnly`）。它按写入规则检查草稿，不改动卡片。每行一个问题，最后一行是 `faults: N`。
4. **修正**：按问题行改草稿，再运行一次自查。最多运行三次。
5. **回复**一行 JSON。

## 草稿格式

任务文件已经给出带绑定字段的空草稿。只填 `calls` 和 `dispositions`，其余字段原样保留：

- `calls`：每项 `{"tool":"edit_card","arguments":{"at":"缺口卡片地址","base_receipt":"该卡的写入凭据","owned_paragraph":{"text":"一句带关系词的链接句"}}}`。这句就是这张卡补的链接句；不要改正文的其余部分。
- `dispositions`：每项 `{"at":"缺口卡片地址","outcome":"no_link","reason":"一句话理由"}`。没有真实关系时用 `no_link`（即 none），不要编造关系。卡片自己已经有有效关系、只是缺口已由别处补上时，用 `already_linked`。`already_linked` 只在这张卡**自己的正文**里已经有一句带关系词（依赖、基于、例示、印证、对照、区别、放宽、推广、对应、类比、参照、反驳、批评）的链接句、并且链接指向本组以外的卡时才成立；别的卡链接到它、它的后继卡或子卡、来源行里的链接都不算。拿不准时给这张缺口卡写一句链接句。只处理缺口清单里的卡片。
- 锚点卡：它的 `在全书中的位置` 段由本任务写，段落必须以“在全书中的位置”开头。任务文件写明锚点当前状态：`anchor_position_missing` 才写这一段；`anchor_position_duplicate` 或 `anchor_position_unlinked` 只记 `no_link` 并写明原因。锚点已有这一段时绝不追加第二段。
- 每个缺口卡片恰好一个结果。清单之外的卡片会被脚本拒绝。

## 写链接

- **Link 写在使用它意思的那句话里**，关系词紧贴在 Link 前：`依赖`、`承接`、`例示`、`对照`、`放宽`、`推广`、`对应`、`反驳`。一句说明理由，不写“相关”。
- 没有固定的 Link 条数：有真实关系才写，没有就记 `no_link`。不要为凑数加“关联：”清单，也不要为了对称而删掉有用的 Link。
- 只链接已存在的地址。人类工作区的卡片可以链接，不能修改。不建主题、不移动、不删除。只链接文献树的卡：不链接主题树的卡，也不写枢纽卡（助手会拒绝，`literature_only`）。
- 不明写全书本地编号（`式 (12)`、`§2.1`）来代替内容；确有必要时把编号放在内容之后。

## 卡片语言

你写的句子遵守 ASD-STE100 改写成的中文规则。经理已通过 `skills` 把 `asd-ste100-zh` 技能交给你：先按该技能写。下面是本项目的具体规则，与技能不同时，以下面为准。链接和公式不计入句长。

1. 一句只说一件事。描述句最多 40 字。
2. 不用分号 `；`，写成两句。
3. 主动语态，写出动作者。动作用动词，不写 `进行分析`、`作出决定`。
4. 一个术语一个意思：用卡片里已有的词，不轮换同义词。
5. 一个名词短语最多两个“的”。
6. 保留原书的语气。不堆叠限定，不用褒扬词（`值得注意的是`、`在某种程度上`、`精妙`、`深刻`）。

## 自查

`SELF-CHECK` 行是 `zt-digest link-finish ... -CheckOnly`。它检查：

- 绑定字段是否对应这次的单元和输入；
- 每个缺口卡片是否恰好有一个结果；
- 写入的链接句是否有关系词（L1）和理由（L2），是否真的通到本组之外的卡片；
- 锚点段是否以“在全书中的位置”开头，是否只写了一段。

改到 `faults: 0` 为止。三次后仍有问题，照常回复，并在 `errors` 里写出剩下的问题。

完成后只回复一行 JSON，不加其他文字：
`{"group":N,"linked":写入的卡片数,"none":记 no_link 的卡片数,"errors":"无或一句话"}`
