# 任务说明（所有组共用）

你负责把《{{TITLE}}》（文献卡 `[[{{KEY}}]]`，位于 ZET 代理工作区的文献区）中分配给你的小节消化为本书文献树里的 ZET 卡片。你只写本书的文献树：不新建主题，不写主题树的卡，不写枢纽卡，也不链接主题树的卡。主题树、枢纽和词条索引由另一个工作流（zt-idea-grow）以后从文献树长出来。按已加载的 `zettelkasten` skill 撰写、放置和链接卡片。全部卡片用中文。本说明之后只附上你的组信息和你的小节原文；全书其他部分和现有卡片都在磁盘上，按需自己读取，不要通读全书。

## 磁盘上的资料（只读，不要修改）

- **全书索引** `{{INDEX}}`：每个小节文件对应的章节、所属组和锚点卡片。很短，先读它。
- **小节文件** `{{STAGING}}\sections\sNN.md`；合并全文 `{{STAGING}}\book.zh.md`。
- **现有文献卡片快照**：组信息中给出的 snapshot 文件，列出所有文献树卡片的地址和标题（本书和其他书，代理与人类工作区）。
- **双语原文** `{{SOURCE}}`：只在需要核对英文原文时读取相关段落。
- 卡片正文：需要时用助手脚本的 `get_card` 或 `search_cards` 读取。

先搜索、再精读：用 `Select-String -Path "{{STAGING}}\sections\*.md" -Pattern '敲竹杠|剩余控制权' | Select-Object -First 15` 找出某个概念出现在哪些小节，再只打开最相关的一到三处（`-Context 2,4` 往往就够），不要整份读入。

## 步骤（全程最多 7 条命令）

1. **探索（一条命令）**：在同一条 pwsh 命令里读快照，并对你这部分的 3–5 个核心概念做 `Select-String`。组信息里已列出用词最接近的其他小节，先从它们看起；全书索引只在需要时读。
2. **精读（可选，一条命令）**：只读上一步找到的最相关段落（`-Context` 或 `Get-Content` 的行范围），弄清你的小节承接哪些部分、被哪些部分用到。
3. **写入（一条命令）**：写完全部卡片并改写锚点；失败时按 resume 行重跑算作一条。
4. **自查（一条命令）**：运行组信息里的 `SELF-CHECK` 命令。它列出你的卡片和锚点的每个问题，每行一个：地址、规则号、句子，最后一行是 `faults: N`。
5. **修正（可选）**：有问题时，用一条写入命令改正全部问题（`edit_card`），再运行一次 `SELF-CHECK`。
6. **回复**一行 JSON。

自查命令是 `zt-check`：它按检查阶段的同一套规则检查你写的卡片，不改任何卡片。你不必猜哪些写法合规：改到它报告 `faults: 0` 为止。最多运行三次。三次后仍有问题，照常回复，并在 `errors` 里写出剩下的问题。

每多一条命令都会重读整个对话，所以把读取合并起来，不要逐个文件、逐张卡片地读写，也不要为确认写入结果再读一遍。

## 写入 ZET

你没有原生 zt 工具。用一条 pwsh 命令把全部调用通过 here-string 交给助手 `zt-digest call`（`'@` 必须单独占一行、顶格），命令末尾照抄组信息中的 `-Log` 参数，它记录你写的卡片：

```
@'
[{"tool":"create_successor","arguments":{"at":"{{KEY}}/7","kind":"side","title":"……","body":"……"}},
 {"tool":"create_successor","arguments":{"at":"@@0","kind":"direct","title":"……","body":"……"}},
 {"tool":"create_successor","arguments":{"at":"{{KEY}}/7","kind":"side","title":"……","body":"…… [[@@1]] ……"}},
 {"tool":"edit_card","arguments":{"at":"{{KEY}}/7","title":"……","body":"……"}}]
'@ | zt-digest call - -Log "…"
```

- 字符串参数中的 `@@N` 替换为第 N 个调用（从 0 起）返回的地址，只能指向**更早**的调用：先建被链接的卡片，再建链接它的卡片；互相链接时最后用 `edit_card` 补回指。
- 输出每行一条：`N ok <地址>`；失败为 `N error <原因>` 并停止，随后一行 `resume: -From N -Addresses …`。只修改第 N 个调用，用同一 here-string 重跑，并在命令末尾加上这两个参数；已成功的调用不会重复执行。
- 工具：`create_successor`（at, title, body, kind: direct|side, type: idea|event|model, level: concept|formal）、`edit_card`（at, title, body, type, level）；读取用 `get_card`（at）、`search_cards`（query, limit）。人类工作区只读，可以链接它的文献卡。不要删除或移动卡片。助手只接受本书文献树里的写入：`create_topic`、主题树的卡、枢纽卡和指向主题树卡片的 Link 都会被拒绝（`literature_only`）。
- **来源位置**：每个 `create_successor` 调用加一个 `src` 字段，写出这张卡依据的小节文件和行号，例如 `"src":"sections/s05.md:120-160"`。不确定行号时只写文件（`"sections/s05.md"`）。助手脚本把它记入来源日志，不写进卡片；检查阶段按它对照原文核实卡片。
- `body` 只写正文，不要以 `# 标题` 开头。

## 放置

每张卡都放在你的锚点下的本书文献树里：

1. **同一主张已有卡**（本书的卡，或其他书文献树里的卡）：链接那张卡；只写不同的解释或推论，不再写一张同义的卡。
2. **其余的卡**：建在你的锚点下，按下面的论证顺序排列。依附本书才能读懂的内容（模型的推导、对本书设定的解释）按模型卡的规则写；脱离本书也能成立的观点也写在这里，写成能独立读懂的一段。把这些观点整理进主题树是 zt-idea-grow 的工作，不是你的。

- **文献树卡片**：本书的笔记（论断、模型设定、推导步骤、作者对文献的评述），只在你的锚点下建。
- **文献树里按论证排列**：一张卡是另一张卡论证的下一步（由它推出、在它的条件下成立、给出它的结果）时，建成那张卡的直接后继（`"at":"@@k","kind":"direct"`）；一张卡给出例外、对照或旁支时，建成那张卡的侧后继。只有彼此平行、各自开头的主张才作为锚点的侧后继。一个锚点下的侧后继最多约 7 张；更多时，把同一小节的主张接在该小节的首张卡后面。
- **观点卡不接在模型卡后面**：模型卡和它的分卡由模型编译器排布，模型卡的后继只放它自己的分卡。由模型推出的结论写成观点卡，接在锚点或另一张观点卡后面，并在正文里用 `依赖 [[模型卡]]` 或 `例示 [[模型卡]]` 写出它和模型的关系。
- **最后改写你的锚点**（`edit_card`）：标题为这一部分的核心论点（一句话断言）；正文为小节索引，每行 `§2.1 - 该节讲了什么`，再用带理由的句子链接本组最重要的 3–6 张卡片，最后一段以"在全书中的位置："开头，用 2–4 句说明本部分承接哪些部分、引出哪些部分，并链接相应锚点卡片。

## 书中的图

原文里形如 `![图 2.C.1](artifact:…)` 的一行是书中的原图。ZET 已保存这张图，卡片可以直接显示它。它后面常跟着英文图注（`Figure 2.C.1 (left)`）。

- 卡片讲到某张图（`图 2.C.1 画出……`、`如图所示`）时，把这一行**原样**复制进卡片正文，单独成段，放在第一次提到它的那段之后。不要改动 `artifact:` 后面的 64 位地址，也不要自己编造地址。
- 一张图只放进最需要它的卡片：通常是解释这张图的卡片。其他卡片写 `见图 2.C.1`，并链接那张卡片。
- 不要为书中已有的图另画示意图表。书中没有的图才用图表画。
- 原文里没有 `artifact:` 行的图（版式装饰、题号小图）不放进卡片。

## 卡片语言

标题和正文遵守 ASD-STE100（简化技术英语）改写成的中文规则。经理已通过 `skills` 把 `asd-ste100-zh` 技能交给你：先按该技能写。下面是本项目的具体上限，与技能中的数字不同时，以下面为准（检查脚本按这些数字检查）。公式、链接、图表代码和书中原话不受限制。

1. 一句只说一件事：`E 违约。C 清算资产。`，不写 `E 违约，于是 C 清算资产，同时……`。
2. 描述句最多 40 字（公式和链接不计）。在每个新陈述处断句。
3. 不用分号 `；`，写成两句。
4. 主动语态，写出动作者：`C 清算资产。`，不写 `资产被清算。`（书中没有写出动作者时才用"被"）。
5. 动作用动词：`分析`、`决定`，不写 `进行分析`、`作出决定`。
6. 一个术语一个意思：同一个概念始终用同一个词，不轮换同义词。组信息给出本书的术语表 `terms.md` 时，用表中的术语，不用"不用"列的词（检查脚本按此表检查）。
7. 一个名词短语最多两个"的"。
8. 保留原书的语气：原书说"可能"就写"可能"。
9. 不堆叠限定，不用褒扬词：不写 `值得注意的是`、`在某种程度上`、`精妙`、`深刻`。
10. 三个以上的步骤或条件用编号列表。
11. 标题只陈述一个论断，最多 40 字。
12. 卡片要独立可读：标题和正文里不用本书的编号代替内容（`式 (12)`、`命题 3.G.3`、`第 6 章`、`模型 1`、`本节`、`§11.D`）。写出编号所指的公式、命题、模型或步骤本身；编号可以作为次标签留在后面。`第一福利定理` 这类有名字的结论不算编号。
13. 不写没有名字的指代：`那里`、`该卡`、`那张卡`。写出它指的是哪个概念、模型或结论；需要时把 Link 放进同一句。前一句里的名字不算。
14. 标题要和工作区里已有的标题区分开：同一主张写在同一张卡上（用直接后继或改写那张卡，不要另建近似标题的新卡）；不同主张在标题里写出区别。检查脚本的相似标题提示（I6）只作参考，是否同一主张由你判断。

## 卡片规则

- 一卡一观点；标题为一句完整断言；用自己的话，不抄译文；可独立理解；正文约 80–200 字；公式用 `$...$`。
- **公式的 `$` 成对出现**，标题里也一样。草稿和调用用 Write 工具或单引号 here-string（`@'…'@`）写；不要把含 `$` 的文字放进 PowerShell 双引号字符串，`"$A_I"` 会被当成变量吞掉，只剩 `<A_O$`。金额写成 `美元`。检查脚本按 R22 报告没有闭合的公式。
- **Link 写在使用它意思的那句话里。** 说明关系的 Link 放在表达这层关系的句子中，关系词紧贴在 Link 前（`依赖`、`例示`、`对照`、`放宽`、`对应`、`反驳`）。没有固定的 Link 条数，也不要为了凑条数在末尾另加一段"关联卡"。一句里没有真实关系时，就不放 Link。
- **接续另一张卡的第一句写出关系。** 一张卡延续、限定或反驳另一张文献卡时，第一句说出它接续的是哪张卡、哪条主张，例如 `本文的学习外部性放宽 [[Smith2024/2|a]] 的固定技术假设：把技术水平写成可积累的。`。只写 `这扩展了那里` 不算。
- **来源与公式保真。** 来源行写 `来源：[[{{KEY}}]] §2.2`；公式、符号和书中原话原样保留，不要改写。
- 本组约写 6–12 张卡，宁少而精。
