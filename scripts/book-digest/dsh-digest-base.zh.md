# 任务说明（所有组共用）

你负责把《{{TITLE}}》（文献卡 `[[{{KEY}}]]`，位于 ZET 代理工作区的文献区）中分配给你的小节读成**文献笔记**，写在本书的文献树里。你只写本书的文献树：不新建主题，不写主题树的卡，不写枢纽卡，也不链接主题树的卡。主题树、枢纽和词条索引由另一个工作流（zt-idea-grow）以后从文献树长出来。全部卡片用中文。本说明之后只附上你的组任务文件、启动快照、早前上下文包和术语表。

你不调用 zt，也不改任何卡片：你把写入表示成一份 JSON 草稿，脚本核对后再写入。

## 磁盘上的资料（只读，不要修改）

- **组任务文件**：本文件之后紧接的那份 `prompt.md`。它给出草稿路径、两条 `SELF-CHECK` 命令、当前锚点、锚点的 `base_fingerprint`，并附上本组全部小节原文。先读它。
- **共享规则**：本说明的渲染副本，任务文件第一行给出路径。
- **全书索引** `{{INDEX}}`：小节文件、章节、组和锚点卡片的对照表。
- **小节文件** `{{STAGING}}\sections\sNN.md`：本组的原文。`src` 里的行号按这些文件数。
- **现有文献卡片快照**：任务文件给出的 snapshot，列出所有文献树卡片的地址和标题（本书和其他书，代理与人类工作区）。
- **早前上下文包**：任务文件给出的 pack，列出本组之前最多 20 张相关卡片。写卡前先读它；断言"同一主张"前按 pack 里的 locator 读完整张卡，人类工作区的卡只读。
- **术语输入**：任务文件给出的 `terms.md`（存在时先读它），按其用词。
- **双语原文** `{{SOURCE}}`：需要核对英文原文或符号时读相关段落。

## 步骤（全程最多 12 条命令）

1. **读任务文件和早前上下文包（一条命令）**：读组任务文件、pack 和术语表，弄清本组有哪些小节、锚点现在长什么样。
2. **通读本组的小节（一到三条命令）**：读本组全部小节原文，不要只读搜索命中。按带行号的方式读，记下每段的行号：

   ```powershell
   $i=0; Get-Content -LiteralPath "{{STAGING}}\sections\s05.md" | ForEach-Object { $i++; "$i`t$_" }
   ```

3. **写草稿（一条命令）**：把本组全部笔记、模型卡和锚点改写写成 JSON，写入任务文件给出的草稿路径。用一个 here-string 一次写完。
4. **自查（两条命令）**：按顺序原样运行任务文件里的两条 `SELF-CHECK`。第一条检查卡片（规则逐行给出，最后一行 `faults: N`），第二条是覆盖检查 `zt-digest coverage`（`sNN.md:行-行 C1 uncovered "…"` 表示这段没有卡片覆盖，`C2` 表示 `src` 只写了文件名没有行号，最后一行 `faults: N`；`(advisory)` 行不算错，但也要读）。
5. **修正（最多两条命令）**：按两组问题改草稿，再各运行一次自查。两条都打印 `faults: 0` 才算通过；最多运行三次。
6. **回复**一行 JSON。

每多一条命令都会重读整个对话，所以把读取合并起来，不要逐个文件、逐张卡片地读写，也不要为确认结果再读一遍。三次自查后仍有问题，照常回复，并在 `errors` 里写出剩下的问题。

## 草稿

任务文件给出带绑定字段的空草稿。只填 `calls`，其余字段（`schema_version`、`unit`、`token`、`input_hash`、`disposition`）原样保留：

```json
{"tool":"create_successor","arguments":{"at":"{{KEY}}/7","kind":"side","title":"……","body":"……","src":"sections/s05.md:120-160"}}
```

- 每项是一次写入提案，只有 `tool` 和 `arguments` 两个字段。可用 `create_successor`（at, title, body, kind, type, level, src）和 `edit_card`（at, title, body, base_fingerprint）。
- 字符串参数里的 `@@N` 换成第 N 个调用（从 0 起）返回的地址，只能指向**更早**的调用。
- **每张新卡的 `src` 写小节文件和行号范围**：`"src":"sections/s05.md:120-160,171-175"`。覆盖检查按它把原文段落算到卡片上；只写文件名会被记为 C2，没有卡片的段落会被记为 C1。
- 改写锚点用 `edit_card`，`at` 是锚点地址，`base_fingerprint` 照抄任务文件给的值。
- 新卡一律建在锚点之下：第一张建成锚点的**侧后继**（`at` 是锚点地址，`kind` 是 `side`）；锚点的直接后继位置留给其他组的锚点，不要占用。
- 人类工作区的卡片可以链接，不能修改。不要删除或移动卡片。草稿里只写本书文献树里的卡片。

## 文献笔记

一本书记的是作者的一段论证。**每段写一张笔记**：凡是作者文字的一步（一个论证、一个例子、一个定义、一段对文献的评述），就写一张卡。卡片数目由材料决定：没有固定张数，不要为凑数拆开一段，也不要把几段压成一张。

- **标题**说这段讲了什么，最多 60 字，一行。可以是断言（`地理假说难以解释殖民地之间的制度差异`），也可以是概括短语（`作者对地理假说的三点反驳`）。
- **正文**是按作者顺序写的连贯散文，通常 200–1,200 字。保留作者的归属（`作者认为`、`Acemoglu 与 Robinson 指出`）、限定（`可能`、`在……条件下`）、例子、数字与告诫。不要把作者的话改写成一份提纲。
- **每个术语和符号第一次出现时就解释清楚**；本书术语表里的词按表用词，也可以链接已有术语卡。原文没有给出、由你补上的解释，在那个句子开头写 `（解释）`。
- 一段文字里的意思分几层时，按思路分段，不按字数切。
- 原文自己列了三个以上平行的步骤或条件时，用编号列表；其余情况写连贯的句子。

## 放置

- 本组的阅读线索是锚点下的一条**直接后继链**：第一张卡是锚点的侧后继，后面每一步是前一张卡的直接后继（`"at":"@@k","kind":"direct"`）。
- **例子、离题、脚注、作者对别人工作的批评、对反驳的回应**，建成它们所属那张笔记的侧后继（`"kind":"side"`），不要插进阅读线索。
- 由模型推出的内容写成一张散文笔记，用一句说明这段在做什么，并链接模型卡（`该推导见 [[模型卡]]`）；不要把推导步骤再抄一遍。事件和实证结果同样处理：笔记写上下文，链接那张卡。
- 本书的模型卡按 `dsh-model-cards.zh.md` 的补充说明写，放在锚点下作侧后继，并排在讨论它的卡片之前。
- 同一主张已有一张卡（本书或其他书文献树里的卡）时，链接那张卡；只为不同的解释或推论另写一张卡，不写同义的重复卡。

## 锚点

最后改写本组锚点（`edit_card`）：

- **标题**说出这一部分装的是什么，例如 `殖民起源：制度怎样解释当今繁荣`。
- **正文**先写这一部分的散文摘要（3–8 句：它问什么、怎样论证、得出什么），再写小节索引，每行 `§2.1 - 该节讲了什么`，最后一段以 `在全书中的位置：` 开头，说明本部分承接哪些部分、引出哪些部分，并链接相应锚点卡片。

## 书中的图

原文里形如 `![图 2.C.1](artifact:…)` 的一行是书中的原图。ZET 已保存这张图，卡片可以直接显示它。

- 卡片讲到某张图（`图 2.C.1 画出……`、`如图所示`）时，把这一行**原样**复制进卡片正文，单独成段，放在第一次提到它的那段之后。不要改动 `artifact:` 后面的 64 位地址，也不要自己编造地址。
- 一张图只放进最需要它的卡片；其他卡片写 `见图 2.C.1`，并链接那张卡片。
- 不要为书中已有的图另画示意图表。原文里没有 `artifact:` 行的图（版式装饰、题号小图）不放进卡片。

## 链接

- **Link 写在原文建立联系的那句话里**，用这句话说明联系（`作者在第二部分回到这个问题`、`这一结论推广了……`）。不要求在 Link 前放关系词：原文说出了一种关系（`依赖`、`例示`、`对照`、`放宽`、`对应`、`反驳`）时，就把那个词写进句子，档案据此记下关系种类；没有这种词就是普通引用。
- 没有固定的 Link 条数。原文没有联系就不放 Link，也不要为凑数在末尾另加"关联卡"一段。
- 接续另一张卡时，不必在第一句先写关系；把联系写进它出现的那句话即可。

## 语言

本任务**不使用** `asd-ste100-zh` 技能（经理传入该技能时忽略它）。只用下面五条：

1. **一个术语一个意思**：同一个概念始终用同一个词，不轮换同义词；本书术语表 `terms.md` 给出的词照用，不用"不用"列的词。
2. **不用褒扬词和空话**：不写 `值得注意的是`、`在某种程度上`、`精妙`、`深刻`、`众所周知`。
3. **用连接词把句子连起来**：`因为`、`因此`、`但是`、`换言之`、`于是`，一段围绕一条思路；不要写成一串互不相连的短句。
4. **编号列表只用于三个以上平行的步骤或条件**。
5. **公式、引文和图中的行逐字保留**：`$...$`、`$$...$$` 和 `![图 …](artifact:…)` 原样抄，不改写、不翻译、不补全。

## 格式与保真

- 每张卡的正文都有一行来源行：`来源：[[{{KEY}}]] §2.2`（小节号和本节的实际出处）。
- **公式的 `$` 成对出现**，标题里也一样。草稿用 Write 工具或单引号 here-string（`@'…'@`）写；不要把含 `$` 的文字放进 PowerShell 双引号字符串，`"$A_I"` 会被当成变量吞掉。金额写成 `美元`。检查脚本按 R22 报告没有闭合的公式。
- 正文不要以 `# 标题` 开头；标题只写在 `title` 字段。
- 公式、符号、书名和书中原话原样保留，不改写。

## 回复

写入草稿、运行完两条自查后，只回复一行 JSON，不加其他文字：
`{"group":N,"cards":写入卡片数,"models":模型卡数,"events":事件卡数,"anchor":"锚点地址","errors":"无或一句话"}`

## 通用写入规则（每个写卡的任务都适用）

- **保留术语写法。** 正文里已有的术语链接 `[[词@地址]]` 原样保留；要提到一个已有术语、而正文没有现成链接时，写术语本身的文字，不要自己造链接。
- **不编造、不绕过。** 不要编造地址或链接目标，也不要为了让检查通过而换同义词、换关系词或改掉事实里的用词。
- **先自查。** 任务文件给出自查命令时（`SELF-CHECK:` 行，或 `CHECK:` 与 `LIMITS:` 两行），原样照抄，写完（或改完）就运行；最后一行是 `faults: 0` 才算通过，最多运行三次。命令没有打印 `faults:` 行（或任务文件指定的状态行）时，视为没有自查。
- **`card_check` 是内容问题。** 写入被拒绝为 `card_check` 时，拒绝里的每个故障行就是要改的内容：按它们改写后再写一次，仍在这一轮限定的修正次数以内。它不是脚本、服务或网络故障，不要原样重试。
- **`card_locked` 是选址决定。** 写入被拒绝为 `card_locked` 时不要重试，不要换 Access，不要改用别的写入路径或直接改数据库：保留已写好的答案，按任务文件的要求回复，并写明被拒绝的地址。
