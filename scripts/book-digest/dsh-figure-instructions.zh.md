# 图表核对任务说明

你为一本书的一组卡片核对图表：哪些卡片讲到的内容和哪些图表有关。脚本会把图表放进你指出的卡片，读者一边读卡片一边看图，理解得更快。你只写一个 JSON 文件，不调用 zt，不改卡片。

本说明之后附上两份文件：**全书图表表**（每张图或表的编号、种类、图注和图像说明；图像说明是看过原图的人写的，告诉你图上画了什么），以及**本组任务文件**（本组全部卡片的正文、答案路径和 SELF-CHECK 命令）。

## 判断

逐张读本组的卡片，再对照图表表，找出和这张卡片内容有关的每一张图表。判断时以图像说明为准，不要只看编号或图注。书中没有编号的图，表里用 `F12` 这样的编号，照样可以选。

- **卡片没有提到这张图也算。** 只要图表画的、列的正是卡片讲的地点、建筑、人物、时期、制度、数据或论证，就算有关。这是本任务的重点，提到编号的卡片脚本已经找到了。
- **一张图可以放进很多张卡片，几十张、上百张都可以。** 不要因为别的卡片已经用过它就不选。
- **一张卡片可以有多张图**，有关的都写上。
- **图要能帮读者读懂这张卡片。** 只是同属一本书、同属一章、或只是都提到"巴格达"这样的大词，不算有关。拿不准时，问自己：读者读这张卡片时看这张图，会不会更明白卡片讲的东西；不会就不选。
- 没有有关图表的卡片不写。

## 答案

把结果写入任务文件给出的答案路径（UTF-8 的 JSON），一次写完：

```json
{"links": [{"card": "卡片地址", "figures": ["7.8", "7.9"]}]}
```

`card` 只能写本组任务文件列出的地址，`figures` 只能写图表表里的编号，照抄，不改写。全组都没有有关图表时写 `{"links": []}`。

## 自查

写完后原样运行任务文件里的 `SELF-CHECK:` 命令。每行是一个问题，最后一行是 `faults: N`。改到 `faults: 0`，最多运行三次。

## 回复

只回复一行 JSON：`{"cards":卡片数,"links":写出的卡片—图表对数,"errors":"无或一句话"}`
