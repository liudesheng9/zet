# Markdown Cards and the Slip-box GUI Design

Status: implemented in zt 0.2.0.

## Source Authority

- `CONTEXT.md` defines the project language. This document changes the stored form of a Card and adds the GUI.
- Earlier design documents remain authoritative except where this document replaces the `<--->` Card text format, the automatic Reverse link wording, and the Session card view layout.

## Goals

1. Every Card is one Markdown document, identical for the shell, the Session, the dump, and the GUI.
2. The CLI never renders Markdown: it shows and edits the stored Markdown verbatim.
3. A local GUI (`zt gui`) renders Cards and shows the card space in a way that follows the addressing model instead of hiding it.

## Locked Card Text Format

```markdown
# <title>

<body Markdown>

<!-- zt:reverse-links -->
## Reverse links

- [[<source>]] <source title>
```

- The title is the leading ATX level-one heading (`# Title`). Blank lines before it are ignored; a closing `#` run is dropped. Topic and Regular Cards must have a non-empty title; otherwise saving fails with ``card text must start with a `# Title` heading`` or `card title cannot be empty`.
- The body is everything between the heading and the Reverse link marker, with leading and trailing blank lines removed.
- `<!-- zt:reverse-links -->` separates the body from the generated Reverse link section. It is optional when editing (missing means no client Reverse links), and a text with more than one marker line is rejected.
- Everything after the marker is generated by ZT on every write and is never taken from the client. With no inbound Links the marker ends the text. With inbound Links the section is a `## Reverse links` heading followed by one `- [[source]] Title` list item per source, deduplicated and ordered by address.
- Canonical stored text is `# {title}\n\n{body}\n\n<!-- zt:reverse-links -->\n{reverse}`, with the body paragraph omitted when empty.
- Literature Card titles still come from BibTeX. When editing Literature Card text the heading is optional and any heading the client writes is replaced by the BibTeX title.
- New Cards open with the template `# {title}\n\n\n<!-- zt:reverse-links -->\n`: the heading, a blank line, an empty body line, and the marker. The terminal editor places the caret after `# ` when the title is empty.

## Locked Link Rules in Markdown

- `[[target]]` Link macros are recognized in Markdown prose only. Text inside inline code spans (any backtick run length) and fenced code blocks (```` ``` ```` or `~~~`, up to three spaces of indent, unclosed fences run to the end) is never a Link, is not validated, and is not rewritten on move or rename.
- All other Link validation, Broken link, rewrite, and Reverse link rules are unchanged.

## Locked Migration

- The archive records `card_format = markdown` in `metadata`.
- `zt up` (and any command that requires the service) converts an archive without that marker: each `<--->` Card becomes `# {title}` plus its body, then Reverse links are regenerated in the new format, all in one transaction.
- Before converting any Card the database is copied with `VACUUM INTO` to `zt.sqlite3.pre-markdown-<unix-seconds>.bak` in the archive root. The conversion runs once.

## Locked CLI Presentation

- The Session card view shows `location:` (or `citation key:` with `metadata:` and the BibTeX), then the stored Markdown line for line, then the clickable `parent:`, `direct:`, and `side:` lines.
- Link macros in prose lines stay clickable; lines inside fenced code blocks are plain.
- Shell editing through `$EDITOR` still uses a `.zt.md` temporary file.

## GUI

`zt gui [--port <port>] [--no-open]` requires the service to be up, registers as a Session (so `zt down` waits for it), and serves a single-page app on `127.0.0.1` (default port 4717, falling back to a free port). It opens a chromeless Edge or Chrome app window when available, otherwise the default browser. It stops on Ctrl+C or with the window's power button.

### Security

- Loopback only. Requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` are rejected (DNS rebinding).
- Every `/api/` request must carry the per-launch random token embedded in the page (`X-ZT-Token`).
- Markdown is rendered with raw HTML shown as text, and the page is served with a strict Content Security Policy.

### Same rules as the CLI

- Every change goes through the same functions as the shell and Session: edit lock, Card validation, Link validation, delete and move plans, Citation-key rename mapping, and Reverse link regeneration.
- Delete, move, and Citation-key rename show the same verification lines and require typing the same confirmation (`delete`, the Tree root address, or `move`).
- Saving an edit is refused when the Card changed since it was opened.
- The command bar accepts the Session vocabulary (`go`, `root`, `up`, `ls`, `t`, `l`, `n`, `b`, `e`, `del`, `mv`, `stats`, `status`, `lsbk`, `help`, `q`) with the same availability rules and error messages.
- Open windows poll a fingerprint of all Cards and refresh when the shell or a Session changes something.

### Presentation

- **Cabinet** (left): Topic and Literature drawers with card counts and excerpts, plus full-text search.
- **Desk** (ROOT): each tree as a stack of index cards.
- **Folgezettel map** (a tree): the address is the layout. A Direct successor continues its column downward; every Side successor starts a new column to the right, one row below its parent. Links draw as dashed arcs; the Pointer card is highlighted and kept in view. Arrow keys walk parent, direct, and side successors.
- **Constellation**: a force-directed view of every Card, colored by tree, with tree edges and Link arcs.
- **Reader** (right): the Card as an index card with rendered Markdown, Link chips, Reverse links, navigation, actions, and the stored Markdown.
- **Writing desk**: raw Markdown beside a live server-rendered preview, `[[` Link completion, BibTeX checking for Literature Cards, `Ctrl+S` to save and `Esc` to cancel.
